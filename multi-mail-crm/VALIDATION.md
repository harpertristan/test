## Границы проверки

Проверки выполнены в этой изолированной среде. **На живой VPS изменения не публиковались**:
ссылки на диалоги Codex не передают SSH-доступ. Для публикации подготовлены
`integration/install-existing.sh`, Caddyfile, overlay и инструкция.
Установщик на VPS здесь не выполнялся; для него нужны существующая конфигурация
и доступ администратора. Он применяет только новый проект и общий Caddy, не старые приложения.

Живые Zoho EU/Gmail/IMAP/SMTP/OpenAI/Telegram с учётными данными пользователя не
проверены. Ссылка ChatGPT с ключами недоступна через прокси этой среды; ключи оттуда
не заявляются как перенесённые. На VPS установщик может прочитать совместимые переменные
из прежнего `/srv/play-scout/app.env`, не меняя его и не печатая значений.

Нагрузка 300 реальных ящиков на целевом VPS не измерялась. Для 300 ящиков одной
Zoho-организации квоты 30 req/min недостаточно для polling раз в 120 секунд:
нужны webhook и/или повышенная квота. Ресурсы совместного VPS необходимо учитывать
отдельно; старым инструментам новые ограничения CPU/RAM не навязываются.

## Обновление провайдеров: Inbox.eu / Zoho EU / Google

Новые ящики используют только `inbox_eu`, `zoho_eu`, `gmail`. Mail.ru больше не
предлагается и не обслуживается. Миграция `0003` проверена на отдельной временной
PostgreSQL: прежний `@inbox.eu` переносится на новый коннектор с очисткой курсора,
остальные старые IMAP-записи отключаются без удаления истории. Alembic check: изменений нет.
Полный набор: **38 pytest passed**. Проверены TLS endpoints и SMTP на моках,
чтение BODY.PEEK без снятия UNREAD и отказ от старого типа в API создания ящика.
Production-сборка TypeScript/Vite прошла. Chromium проверил три пункта провайдера,
пароль только для Inbox.eu, OAuth-подсказки, одно поле в форме компании,
виртуализацию 320 ящиков, уведомления и мобильный экран без ошибок JavaScript.
Реальные подключения Inbox.eu, Google и Zoho с пользовательскими реквизитами
не проверялись. Официальная справка help.inbox.eu недоступна из облачной среды
из-за сетевого ограничения; настройки Inbox.eu нужно подтвердить при первом подключении.

200 для актуальной схемы, 503 при устаревшей и восстановление после возврата версии.
На отдельной временной PostgreSQL повторно проверены upgrade 0002 → 0003,
сохранение истории, alembic check и весь серверный набор: **39 passed**.
У Redis Pub/Sub отключён таймаут чтения при простое; обычные Redis-команды сохраняют
ограниченный таймаут, отмена задачи по-прежнему закрывает подписку.
