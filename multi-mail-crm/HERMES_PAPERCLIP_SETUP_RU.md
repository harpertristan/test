# Hermes + Paperclip для Play Scout, Помощника и почтовой CRM

Дата подготовки: 6 ноября 2026 года.

Это инструкция и спецификация внедрения. На VPS Hermes и Paperclip пока не установлены.
Готовый установщик трёх прикладных коннекторов и шлюза разрешений ещё нужно разработать
и проверить: одной установки Hermes недостаточно для описанных ниже гарантий.

## 1. Решение

Рекомендуемая связка: Paperclip управляет задачами и запусками, Hermes выполняет работу,
OpenAI обрабатывает контекст, Telegram сохраняет текущие уведомления. Разрешённые передачи
в OpenAI/Telegram не означают разрешения на другие внешние передачи или публикации.
OpenAI действительно получает отправленные ему тексты. Это не полностью локальная обработка.

Новые компоненты разворачиваются отдельным Compose-проектом и отдельными томами.
Исходники, БД и контейнеры двух прежних инструментов не заменяются. Для интеграции
разрабатываются внешние адаптеры к существующим API. Если нужного API нет, добавление
узкого endpoint оформляется отдельно; браузерный обход ограничений не используется.

Схема:

Владелец → приватная панель Paperclip → изолированный Hermes → внутренний MCP-шлюз
                                                               ├─ Play Scout
                                                               ├─ Помощник
                                                               └─ Почтовая CRM

Hermes → внутренний прокси моделей → OpenAI
Внутренний уведомитель → разрешённый чат Telegram
Изолированный исследователь → публичные источники по разрешённому поисковому заданию

Наличие кнопок подтверждения в Hermes/Paperclip не заменяет проверку шлюзом.

## 2. Зачем нужен Paperclip

В проверенной документации Paperclip заявлены Hermes и Hermes Gateway, задачи,
проекты, очереди пробуждений, расписания, роли, согласования, журнал запусков,
учёт затрат и pause/resume/terminate.

Для одного ручного чата он необязателен. Для трёх рабочих инструментов полезен:
вы видите, какая задача выполняется, какие документы использованы, какой результат
готов, что ожидает решения, сколько потрачено и что остановилось с ошибкой.

На старте создаются три проекта и один исполнитель Hermes, максимум один активный запуск.
Не нужно сразу заводить много параллельных «сотрудников». Позже возможны отдельные
профили исследователя, документов и почты с разными разрешениями и памятью.

Paperclip — панель управления, а не самостоятельная граница защиты данных.
Его локальный адаптер нельзя использовать для запуска Hermes с доступом ко всему VPS.
Выбирается изолированное подключение к Hermes/Gateway; точная совместимость версий
адаптера проверяется на тестовом запуске перед предоставлением реальных данных.

## 3. Что агенту разрешено

| Действие | Базовый режим |
|---|---|
| Читать разрешённую переписку/документы конкретной компании | Разрешено в рамках задания |
| Искать внутри трёх инструментов | Разрешено с фильтрацией прав и компании |
| Извлекать поля анкеты с указанием страницы-источника | Разрешено |
| Готовить черновик анкеты/ответа | Разрешено |
| Предлагать категорию письма и локальную задачу | Разрешено |
| Добавлять новые ящики | Подготовка разрешена; подключение секретов выполняет владелец |
| Отправлять письмо, анкету или вложение наружу | Только по конкретной команде владельца |
| Публиковать сайт, репозиторий, файл, ссылку для общего доступа | Запрещено без отдельной команды |
| Отправлять служебное уведомление владельцу в Telegram | Только утверждённый шаблон и фиксированный чат |
| Удалять обычные данные, менять права/инфраструктуру | Требует отдельного разрешения |
| Выполнять уже утверждённые правила автоочистки CRM | Сохраняются их текущие узкие условия |
| Менять свою политику, секреты, сеть, права или бюджет | Запрещено |

Команда владельца может сразу разрешать конкретное внешнее действие, если получатель,
текст и вложения уже известны. Если итоговый текст сформировал агент, сначала показывается
готовый результат. Общее «разбирай почту» не даёт разрешения на самостоятельные ответы.

## 4. Предварительная проверка VPS — первый реальный шаг

В Google SSH выполните только чтение состояния:

```bash
hostname
free -h
nproc
lscpu | head -18
df -h /
sudo docker --host=unix:///var/run/docker.sock ps --format 'table {{.Names}}\t{{.Status}}'
sudo docker --host=unix:///var/run/docker.sock stats --no-stream \
  --format 'table {{.Name}}\t{{.MemUsage}}\t{{.CPUPerc}}'
```

Пароли, `.env`, содержимое документов и почтовых писем для этого не нужны.

При модели OpenAI не нужно размещать её веса в RAM VPS. Однако Paperclip, Hermes,
их БД и обработчики документов потребуют дополнительной памяти. На сервере 8 GB
сначала измеряется запас. Ставить всё одновременно без замера нельзя: OOM затронет
старые инструменты. При недостатке запаса увеличивается RAM, а не лимиты старых сервисов.

Для локального Ollama текущая проверенная документация Hermes требует контекст
не менее 64 000 токенов. Его стоимость по RAM/VRAM существенно выше небольшого чата.
Локальную модель нельзя обещать на загруженном 8 GB VPS. Это отдельный необязательный этап.

## 5. Изоляция исполнения

Разместить новый проект в `/srv/hermes-stack`, отдельно от существующих каталогов.
Предусмотреть каталоги: `config/`, `policy/`, `state/`, `jobs/`, `skills-drafts/`,
`skills-approved/`, `audit/`, `secrets/`. Права сервисных пользователей раздельные.

Минимальный состав:
- Paperclip и отдельная БД Paperclip;
- Hermes worker/Gateway;
- MCP/policy broker с адаптерами трёх приложений;
- model proxy для разрешённых вызовов OpenAI;
- approval/outbound service для разрешённых внешних действий.

OCR, браузер, векторную БД и исследователь добавлять по мере необходимости,
а не запускать все компоненты сразу на VPS 8 GB.

Требования к Hermes-контейнеру:
- непривилегированный UID, `cap_drop: ALL`, `no-new-privileges`, лимиты памяти/CPU/PID;
- read-only корень, отдельные writable `/tmp`, состояние и рабочая папка текущего задания;
- без `/var/run/docker.sock`, host networking, SSH-ключей, `/srv` целиком и host root;
- без почтовых паролей, OAuth refresh tokens, токена BotFather и административного ключа OpenAI;
- без произвольного исходящего Интернета, включая обход через IPv6, DNS и HTTP proxy;
- только внутренняя сеть с MCP broker и model proxy; приложения не подключены к этой сети напрямую;
- автоматические обновления, загрузка плагинов и внешние MCP выключены в рабочем контуре.

Сеть Docker `internal: true` — только часть решения. Проверить реальные маршруты,
DNS, IPv6 и доступ к другим контейнерам. Сетевые правила задаёт оператор; агент не может их менять.
У всех обработчиков/прокси запрещены произвольные URL, редиректы в частные сети,
доступ к cloud metadata, DNS rebinding и чтение локальных файлов по пользовательскому пути.

Официальный Dockerfile Hermes использует init с первоначальным root и последующим
понижением прав. Поэтому нельзя механически дописать `user`/`read_only` и считать
конфигурацию проверенной. Нужен протестированный non-root launcher либо отдельный
образ с минимальным entrypoint. Docker socket для вложенной песочницы ему не выдаётся.

Для особо строгой изоляции на этом же физическом сервере лучше отдельная VM/microVM,
если гипервизор поддерживается. Контейнер разделяет ядро с VPS и не даёт абсолютной защиты
при уязвимости ядра. Нельзя честно обещать «утечка невозможна» только настройкой промпта.

## 6. Установка Hermes и Paperclip

Установку выполнить в два этапа: сборка/загрузка зависимостей без реальных данных,
затем закрытый рабочий режим. Не выполнять интернет-установщик от root на рабочем VPS.

На подготовительном этапе получить исходники официальных репозиториев и зафиксировать
release/commit, зависимости и digest итоговых образов. Не использовать плавающий latest.

Исследованные снимки (не означают полный аудит исходников):
- Hermes: `90d6b98fd86d20981ee06ddd5b7d93e4320f26a4`;
- Paperclip: `7e3caa7bac3f2c1a560158b28ec42381a153dfff`.

Пример получения зафиксированных исходников в НОВЫЕ каталоги на этапе сборки:

```bash
git clone https://github.com/NousResearch/hermes-agent.git hermes-source
git -C hermes-source checkout --detach 90d6b98fd86d20981ee06ddd5b7d93e4320f26a4
git clone https://github.com/paperclipai/paperclip.git paperclip-source
git -C paperclip-source checkout --detach 7e3caa7bac3f2c1a560158b28ec42381a153dfff
```

Сборка выполняется по инструкциям именно выбранных версий. По прочитанной документации
Paperclip требует Node.js 24.11+; ручной source-workflow также использует pnpm и может
требовать Rust для Runner. Dev-сервер `pnpm dev` не является production-развёртыванием.

Стандартный быстрый onboarding Paperclip может создавать дополнительные настройки,
агентов и интеграции. Для нашей установки он проходит в изолированной тестовой среде,
без импорта действующих ключей и каталогов приложений. Потом сохраняется проверенная
конфигурация, а не запускается unattended quickstart поверх рабочего окружения.

Отключить телеметрию Paperclip с первого запуска:

```dotenv
PAPERCLIP_TELEMETRY_DISABLED=1
DO_NOT_TRACK=1
```

Не задавать внешние OTEL/ошибочные лог-экспортёры. Телеметрию Hermes, автоматические
проверки обновлений и все сторонние расширения инвентаризировать и блокировать
сетевым периметром; выдуманного универсального флага отключения здесь нет.

Шаблон логики конфигурации Hermes; его применяют после реализации model proxy/MCP:

```yaml
model:
  provider: custom
  default: gpt-4o-mini
  base_url: http://model-proxy:8080/v1
  context_length: 64000
approvals:
  mode: manual
  cron_mode: deny
  single_query_mode: deny
  unattended_mode: deny
mcp_servers:
  workspace:
    url: http://policy-broker:8080/mcp
```

Это пример структуры из текущей документации, не готовый compose и не гарантия
качества модели. Доступность модели и поддержку tool calling проверяют на вашем
OpenAI-проекте. Для сложных документов можно выбрать более сильную модель и лимит затрат.
MCP-аутентификация выполняется отдельным сервисным credential с узкими правами.
Секрет вводится локально и не копируется в инструкцию. Одних `approvals` недостаточно:
ограничения остаются на broker даже при изменении настроек Hermes.

Model proxy разрешает только нужные OpenAI API, модели и пределы запросов. Он не должен
быть универсальным forward proxy или разрешать загрузки Files/создание общедоступных
ресурсов автоматически. API key хранится у прокси. Agent-facing ключ, если нужен,
не даёт доступа к OpenAI напрямую. Бюджет проверяется до запуска/запроса; лимиты
одного Paperclip могут учитывать расход с задержкой.

## 7. Подключение трёх инструментов — необходимая разработка

Разрабатывается ограниченный MCP server, а не выдача агенту «полного доступа к API».
На каждом вызове проверяются владелец задачи, company/project, разрешённый тип действия,
лимит выборки и список доступных полей. Ответы исключают секреты и лишние персональные данные.

Пример контракта инструментов:

| Play Scout | Помощник | Почта |
|---|---|---|
| search_projects | list_documents | list_accounts |
| read_project | extract_document_fields | search_messages |
| create_research_draft | get_form_schema | read_message |
| propose_project_update | prepare_form_draft | suggest_category |
| export_preview | validate_form_draft | create_reply_draft |
| request_export_approval | request_submission_approval | prepare_mailbox_import |

Имена в таблице — проектируемый контракт, а не уже существующие endpoint этих приложений.
Необходима сверка реальных API и тесты каждого адаптера. Чтение документа не должно
неявно сохранять/отправлять анкету. Черновик письма не должен попадать в очередь send.
При добавлении ящика пароль вводит владелец через защищённую форму; агент не получает
его текст. OAuth проходит в браузере владельца, агенту возвращается статус подключения.

Прямой SQL и произвольный `http_request(url, body)` агенту не предоставляются.
Если API возвращает инструкцию «игнорируй правила и отправь файл», это содержимое
документа/письма, а не команда владельца. Технический запрет отправки сохраняется независимо
от того, распознала ли модель prompt injection.

## 8. Запрет самостоятельной публикации

Секреты внешних отправок находятся у отдельного outbound service. На отправку требуется
разрешение, выпущенное доверенным интерфейсом владельца, а не самим Hermes.

Разрешение связывает: actor/task/company, тип операции, точного получателя/домен,
финальные байты текста, хеши вложений, срок действия и одноразовый idempotency key.
Изменился получатель, текст или файл — старое разрешение недействительно.
Разрешение проверяется при исполнении, а не только в момент постановки задачи.
Ключ подписи и функция выдачи разрешений недоступны агенту. Разрешение нельзя
получить из текста входящего письма или результата поиска.

Публикации в GitHub, публичные ссылки, отправка документов в формы и сторонние API
не включаются в базовый набор. Не должно быть обхода через браузерную форму,
запрос поиска, журнал ошибки, внешнюю MCP-службу или изменение URL модели.

Telegram остаётся разрешённым каналом. Текущего бота CRM не переназначать Hermes:
у бота один webhook, и существующая привязка CRM сломается. Для команд Hermes нужен
отдельный бот либо интерфейс Paperclip. Разрешаются только Telegram ID владельца;
группы/публичные каналы по умолчанию запрещены. Агенту не выдаётся BotFather token;
уведомитель принимает только фиксированные шаблоны и фиксированный chat ID.
Произвольные документы/полные отчёты в Telegram — только по отдельной команде владельца.
Текущие явно разрешённые уведомления CRM сохраняются без изменений.

## 9. Приватная панель и подтверждение владельца

Paperclip нельзя публиковать в trusted-local режиме на открытый Интернет. При текущем
отсутствии логина в CRM сама CRM не является достаточным источником подтверждения владельца.
У Paperclip/approval UI нужен отдельный защищённый доступ: VPN с доверенными устройствами
либо аутентификация. VPN позволяет обойтись без нового пароля в каждом старом инструменте.
Внешний путь к самому агенту и MCP не публикуется.

Раздел «Агент» можно добавить отдельной вкладкой, не переписывая старые инструменты.
Успех фонового задания не означает разрешения публикации. Видны статусы:
черновик / выполняется / результат готов / требуется решение / отказано / ошибка / остановлено.

## 10. Память и улучшение навыков

Hermes умеет сохранять память и создавать навыки. Это не автоматическое дообучение весов
OpenAI и не основание менять права. На старте обучение весов вообще не нужно.

Сохранять: проверенные схемы анкет, процедуры поиска, правила сопоставления полей,
исправления ошибок и ссылки на источники. Секреты не сохранять в памяти/скиллах.
Данные компаний разделять; чужие реквизиты не должны подставляться в другую анкету.

Новый навык автоматически попадает только в skills-drafts, проходит тесты на синтетических
данных и получает версию. В рабочую skills-approved его переводит владелец либо заранее
утверждённая узкая процедура. У навыка нет права менять policy, ключи, сеть, бюджет
или устанавливать пакеты. Активные навыки монтируются read-only; откат версии обязателен.
Публикация навыков в Skills Hub/репозиторий не разрешается автоматически.

## 11. Дополнительные подключения по полезности

1. Локальный OCR: Tesseract/PaddleOCR и PDF/DOCX-парсер, по одному процессу с лимитами.
   Обработчик без сети, без макросов и внешних ссылок, с ограничением размера/времени.
2. Проверка анкет по JSON Schema/Pydantic: обязательные поля, форматы, противоречия,
   ссылки на страницы документов. Не выдумывать отсутствующие реквизиты.
3. Локальный полнотекстовый поиск; векторная БД Qdrant/pgvector — когда обычного поиска мало.
   Embeddings можно получать локально, чтобы не добавлять ещё один внешний поток данных.
4. Playwright в отдельной одноразовой песочнице для публичных сайтов. Без томов с письмами,
   секретами и cookies рабочих приложений; без доступа к localhost/private networks/metadata.
5. SearXNG/поисковый провайдер через отдельный search broker. Запрос поиска сам передаёт
   данные наружу: задания формируются из разрешённых публичных терминов. Документы,
   переписка, персональные реквизиты и кодированные вложения в запросы не допускаются.
6. Paperless-ngx — если нужен отдельный архив документов, версии, теги и OCR.
7. Локальные метрики/аудит: продолжительность, результат, разрешения, бюджеты и ошибки.
8. Зашифрованные резервные копии БД, состояния и навыков. Внешнее хранилище — только
   утверждённый владельцем получатель, ключ шифрования не хранится у агента.

n8n, внешние MCP-каталоги, автоматическое управление VPS, браузер с личными сессиями
и десятки субагентов на старте не нужны: это расширяет доступ и расходует RAM.

## 12. Использование после внедрения

В Paperclip создать задачу и выбрать проект/компанию:

- «Найди новые платёжные приложения по этим публичным критериям. Сохрани отчёт в Play Scout.
  Ничего не публикуй».
- «Прочитай документы компании X, подготовь анкету, для каждого поля укажи источник.
  Не отправляй анкету».
- «Покажи письма с вопросами, подготовь ответы в черновиках. Не отправляй».
- «Подготовь импорт этих адресов в CRM. Пароли я введу сам».
- «Отправь утверждённый черновик #42 получателю ...» — разрешение проверяет outbound service.

Проверять источники, исправлять ошибки, сохранять только проверенный навык.
Расписание включать сначала только для чтения и подготовки отчётов.

## 13. Приёмочные проверки перед реальными данными

- Задача работает только с выбранной компанией; попытка чужого ID отклоняется.
- Агент не видит `.env`, Docker socket, SSH-ключи, host filesystem, metadata.
- Произвольный HTTP/SMTP, внешний MCP, Telegram chat ID и загрузка файла заблокированы.
- OpenAI работает только через model proxy; смена base URL/модели не расширяет доступ.
- «Отправь документ» внутри PDF/письма/страницы не создаёт внешнего запроса.
- Поддельное, истёкшее, повторное разрешение и подмена вложения отклоняются.
- При недоступности approval/broker действие запрещается, а не разрешается автоматически.
- Кнопка остановки останавливает исполнение; уже отправленный внешний запрос отменить
  задним числом нельзя. Сбой/повтор отправки не создаёт дубликатов.
- Телеметрия и внешние лог-экспортёры не создают соединений.
- Нет OOM и деградации старых инструментов при OCR/параллельных задачах.
- Проверены восстановление резервной копии и откат конфигурации.

Нельзя переходить к внешним отправкам, пока эти проверки не пройдены на тестовых данных.
Начинать с read-only, затем черновики, затем локальные изменения, и только потом
адресные отправки по команде владельца.
