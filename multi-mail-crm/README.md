# Третья вкладка: почтовая CRM

В рабочем пространстве теперь три отдельных инструмента:

1. **Play Scout** — `/crm`, исходный коммит `3e429fe`.
2. **Помощник регистраций** — `/assistant/`, исходный коммит `f4319a0`.
3. **Почтовая CRM** — `/mail-crm/`, новый модуль.

**Исходники и данные двух прежних инструментов не меняются.** Их полные снимки
зафиксированы в `integration/tools/`, контрольные суммы — в `integration/sources.lock.json`.
Шлюз добавляет только третью ссылку в выдаваемую навигацию. Старые API, расширение,
файлы, настройки и механизмы доступа сохраняются. Новая почтовая CRM имеет отдельные
PostgreSQL/Redis, очереди и тома.

## Без логинов и паролей CRM

Почтовая CRM открывается сразу. Входа, регистрации, пароля администратора и
пользовательских ролей в интерфейсе нет. Любой, кто может открыть адрес CRM, может
читать и отправлять письма, изменять компании и подключения. Избранное, уведомления
и Telegram-привязка общие. Для их хранения создаётся один технический профиль без
рабочего пароля; старые записи users не удаляются.

Пароли приложений IMAP, OAuth и API-ключи провайдеров остаются необходимы для
подключения самой почты. Они не являются паролем входа в CRM. IMAP и OAuth-секреты
в БД шифруются Fernet, ключ находится только в `.env`. Историческое имя `JWT_SECRET`
сохранено для совместимости: теперь это ключ подписей webhook, а не пароль входа.

## Простой первый запуск локальной копии

Нужны Docker с Compose >=2.24.4 и Python 3.

```sh
cd multi-mail-crm
python3 scripts/init_env.py
python3 scripts/verify_tool_sources.py
docker compose --profile integrated up --build -d --wait
```

Если `.env` уже существует, скрипт не перезапишет его. Для автоматической классификации
заполните в нём `OPENAI_API_KEY` либо настройте Ollama. Затем откройте в браузере
`http://localhost:3000/crm` и нажмите третью вкладку **«Почтовая CRM»**. В ней:
**Управление → Компании → Добавить компанию**, затем **Почтовые ящики → Добавить ящик**.
Для новой CRM создавать администратора и вводить логин не нужно.

Профиль `integrated` создаёт ЛОКАЛЬНЫЕ копии двух прежних приложений на новых томах
для проверки. **Не запускайте его поверх уже работающего сервера:** для добавления
к существующим инструментам используйте [инструкцию VPS](integration/DEPLOYMENT.md).

## Добавление к существующему VPS

Предполагается исходная установка из предоставленной ветки помощника:
`/srv/play-scout`, `/srv/play-scout-workspace`. Разместите этот каталог в `/srv/mail-crm`.
Администратор с уже настроенным SSH-доступом запускает:

```sh
sudo bash /srv/mail-crm/integration/install-existing.sh https://play-scout.34.22.184.67.sslip.io
```

Скрипт проверяет старые runtime-файлы, готовит только НОВЫЙ `.env`, поднимает только
новые сервисы и меняет общую конфигурацию Caddy. Старые приложения не пересобирает,
не перезапускает, не мигрирует. Он сравнивает их container IDs и image IDs и имеет
откат конфигурации прокси. Полные условия и ручной вариант — в
[integration/DEPLOYMENT.md](integration/DEPLOYMENT.md).

В этой сессии доступ к VPS не предоставлен: ссылка на другой диалог Codex не
переносит его SSH-ключи и файлы. Публикация на живом домене **не выполнена**.

## Повседневная работа

- Слева — виртуализированный список ящиков, поиск, компании, избранное и фильтры.
- Нажатие компании открывает сводную переписку всех её ящиков.
- Открытие письма **не снимает UNREAD**. Только кнопка «Прочитано» меняет флаг у провайдера.
- «Отметить: ответил» закрывает ожидание ответа по треду; у фирмы есть общая отметка.
- Отправка из CRM закрывает ожидание после подтверждения почтового сервиса.
- Новое входящее в том же треде снова ожидает ответа.
- Точка и 3px-полоса показывают неотвеченные `add_request/other` старше 48 часов.
  Реклама, отказы и одобрения этот сигнал не включают.
- Настройки → Telegram: одноразовый код `/start ...`; привязка общая для этой CRM.

## Подключения, копии и проверки

- [SETUP.md](SETUP.md): Zoho **EU**, Gmail, Mail.ru, Telegram, OpenAI/Ollama, CSV, backup.
- [ARCHITECTURE.md](ARCHITECTURE.md): очередь, сохранение UNREAD, безопасность, этап 2.
- [VALIDATION.md](VALIDATION.md): выполненные проверки и ограничения.

Для одного только нового backend/frontend без локальных копий старых инструментов
достаточно `docker compose up --build -d`; он поднимет шесть базовых сервисов.
Для рабочего пространства нужен интеграционный шлюз или подключение к существующему VPS.
Не используйте `down -v`: это удаляет тома выбранного проекта.

Живые почтовые подключения требуют ваших OAuth/IMAP/API-данных. При 30 req/min на
одну Zoho-организацию нельзя опрашивать 300 отдельных ящиков раз в 120 секунд:
нужны webhook и/или достаточная квота. Вложения не импортируются; письма отображаются
без выполнения HTML/скриптов. AI-автоответчик не реализован — только предусмотренная схема.
