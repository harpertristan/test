# Play Scout 4.1 — исправления по вашей выгрузке CRM

Версия для Mac и Windows с прежней историей и ключами. Основная установка на Mac обновляется в той же папке, без ручного переноса данных.

## Что исправлено

1. **Компания и сайт.** Ссылка на Calendly / форму записи не становится сайтом банка. Для перехода из статьи требуется соответствие названному продукту. При перепроверке старые документы чужого сервиса исключаются из доказательств; исходные материалы сохраняются для аудита.
2. **Разрешения EMI / PI / MiCA.** Регулятор не принимается за получателя лицензии. Формы заявки и намерения не считаются выдачей. Распознаётся формулировка `decided to issue`; при явной выдаче двух лицензий сохраняются PI и CASP. Дата решения берётся из самой цитаты, год не выдумывается. Разрешение не доказывает открытие бизнес-счёта или EU IBAN.
3. **Материалы источников.** Общие документы регуляторов и инструкции сохраняются в отдельной вкладке. Они не заполняют рабочий список провайдеров и не отправляются в ИИ. Названные события выдачи разрешений продолжают вести к поиску сайта и проверке продукта.
4. **Отсев до ИИ.** Игры, хранилища карт / реквизитов и налоговые инструменты отсеиваются. Функция калькулятора IBAN на сайте банка не превращает весь банк в утилиту. Прочитанный сайт повторно проверяется до запроса модели.
5. **EU IBAN.** Сопоставляются дословные цитаты об одном бизнес-продукте. Убран ошибочный шаблон, из-за которого фраза о партнёре Finom / выдаче IBAN могла стать `unknown`. Личные счета, реквизиты для пополнения, общий счёт, EUR / SEPA и GB / CH / NO не становятся подтверждением бизнес-IBAN страны ЕС.
6. **География.** Нигерийская юрисдикция определяется по провайдеру, регулятору или локальному продукту. Слово Nigeria в списке стран не является достаточным основанием. Учитываются полные сохранённые тексты прочитанного сайта.
7. **Качество разбора.** В карточке есть причины `unknown`, сведения о недостаточном разборе и оригинальный комментарий модели. Комментарий с неправильным языком заменяется описанием проверенных фактов; исходный текст остаётся для аудита. Документы выбираются по релевантности бизнес-счёту / IBAN, а не только по типу источника.
8. **Диагностика.** JSON для ChatGPT содержит исходный заголовок, модель, режим, версии анализа и правил, время проверки, причины отклонения и ошибки источников. Ключи в экспорт не входят.

## Что произойдёт со старым списком

При первом запуске выполняется **локальная перепроверка сохранённых результатов**. Она не обращается к модели или сайтам и не расходует API. Ложные разрешения убираются из производных выводов, нерелевантные записи переходят в автоисключения / материалы источников. Дословные сведения официального продукта могут восстановить подтверждающие факты без нового вызова модели; это отмечается в диагностике.

История находок, комментарии, выбранный ИИ, ключи и ручные исключения сохраняются. Исключённые вручную проекты не отправляются на повторный анализ. Дата обнаружения не считается датой запуска компании.

Подтверждённая очередь ожидания остаётся очередью ожидания после перепроверки: наличие IBAN в описании будущего продукта не делает его уже доступным. Архив ошибочно привязанных источников сохраняется и при повторной перепроверке.

Ваше прежнее ежедневное расписание сохраняется. Если оно включено и пришло время запуска, программа может выполнить обычный поиск согласно вашим настройкам; это отдельное действие от локальной перепроверки.

## Две новые кнопки

- **«Перепроверить сохранённое · без API»** — ещё раз применяет локальные правила к сохранённым текстам. Обновляет производные статусы, сохраняя историю и ручные решения.
- **«Повторить проблемные · N · выбранный ИИ»** — отправляет только оставшиеся проблемные записи выбранной модели, используя сохранённые тексты. Облачный API может расходовать баланс. Проверка новых сайтов, найденных по разрешению, может использовать Brave. Автоматического платного переключения нет.

Если исходный сайт раньше не прочитался, откройте нужную карточку и выполните обычный ИИ-разбор: он попробует заново получить материалы. Увеличивать всю очередь или многократно повторять все находки не требуется.

## Обновить Mac в прежней папке

Откройте новое окно Терминала. Если папка осталась `~/Desktop/play-scout-v31` и вы уже установили 4.0.1 / 4.0.2:

```sh
cd "$HOME/Desktop/play-scout-v31"
npm run update:mac -- --start
```

Обновление создаст резервную копию, заменит код на месте, установит зависимости и запустит CRM. Ожидаемая версия в диагностике — **4.1.0**. Прежние ключи повторно вводить не нужно.

Если команда `update:mac` отсутствует, используйте универсальный блок скачивания из [MAC.md](MAC.md#1-обновить-уже-установленный-play-scout-одной-командой). Для Windows: [WINDOWS.md](WINDOWS.md).

## После запуска

1. Откройте **http://127.0.0.1:3000/crm** и обновите старую вкладку через Command+R.
2. Проверьте «Материалы источников», «Автоисключения» и несколько известных подходящих сервисов.
3. Прочитайте цитаты в карточке. Статус «Подходит» — проверенное заявление источника, а не гарантия открытия вашей компании.
4. Если нужен новый ИИ-разбор, начните с одной карточки или адресной очереди проблемных записей.

Протокол, миграция и интерфейс проверяются автоматическими тестами и в браузере. Нативная macOS и скорость вашей локальной модели в среде разработки недоступны; точность выбранной модели нужно сверить на ваших примерах после запуска.
