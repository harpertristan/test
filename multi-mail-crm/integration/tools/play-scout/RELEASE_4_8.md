# Play Scout 4.8 — источники, объединение провайдеров и уточняющий поиск

## Один провайдер — одна карточка

Основной домен и служебные поддомены support / help / helpdesk / faq / docs / m / www объединяются. Например, satispay.com и support.satispay.com попадают в одну карточку с обоими приложениями и доступными исходниками. Название бизнес-приложения получает приоритет. Разные бренды на произвольных поддоменах / общих BaaS-площадках не сливаются по одному родительскому домену.

Обновление локально переносит соответствующие прежние записи и очередь на общий ID, сохраняет обе заметки и архив исходных решений / анализов. Отметка «Уже в работе» защищает от повторов. Нечёткое объединение только по похожему названию не выполняется.

## Выбор и проверка источников

Источники объединены в сворачиваемые категории с галочками: можно выбрать категорию, отдельные сайты или показанные результаты поиска. Общая кнопка ставит в очередь только выбранные источники. Выбор сохраняется. Для одного обработчика сохраняется последовательная очередь; повтор того же ID запроса не создаёт новую группу запусков. Расписания и отдельный запуск доступны внутри строки; ИИ после сбора включается явно.

«Проверить доступ» выполняет максимум один контрольный запрос Brave на источник и читает найденную страницу; для Google Play — контрольную карточку; для RSS — настроенную ссылку. Различаются отсутствие ключа, пустая выдача, ошибка / лимит и экран входа. Находки и ИИ при этой проверке не создаются. Facebook / LinkedIn через Brave подписаны как публичный индекс.

## Facebook и LinkedIn через Apify

Добавлены два источника API Apify, использующие ваши сохранённые задачи публичного сбора. Одобрение собственного приложения Meta / LinkedIn не требуется. Ключ и ID задач задаются локально: `npm run configure:social-api`.

Проверка доступа читает задачу без запуска сбора. Пробный сбор требует лимита ввода до 20 результатов, ограничивает время, запрашивает денежный предел и показывает ссылку на журнал / известный расход. Полная цена зависит от тарификации актора и настроек Apify. Ежедневные запуски отключены; потерянный ответ платного старта не повторяется автоматически. При остановке отправляется удалённая отмена, неподтверждённая отмена видна.

Пользовательского токена / задач в среде разработки нет: настоящее получение данных из аккаунта ещё не подтверждено. Интеграция проверяется подставным транспортом; активация выполняется после локальной настройки. [Пошаговое подключение](SOCIAL_CONNECTIONS.md).

## Завершение проверки критериев

Разбор читает реальные ссылки на бизнес-продукт, условия и справку до двух переходов: до пяти попыток сайта в экономном режиме, до восьми в подробном. Независимые страницы читаются параллельно с определённым порядком источников. При доступном Brave одна попытка зарезервирована для найденной им страницы. Поисковый фрагмент остаётся подсказкой до чтения самой страницы.

Справка служебного поддомена может подтверждать факты основного провайдера. Личный IBAN не останавливает поиск условий бизнес-счёта. Вход, личный кабинет и чужой домен не используются как доказательство условий этого провайдера.

Явное предложение бизнес-счёта может восстановить два независимых факта из цитаты, даже если EU IBAN неизвестен. EUR / SEPA / реклама для ЕС / лицензия по-прежнему не доказывают выдачу бизнесу IBAN страны ЕС. Подтверждённый неподходящий продукт / запрещённая юрисдикция отсеивается; недостаток сведений сохраняет возможность проверки. Видны числа прочитанных / недоступных страниц и итог подходящих / отсеянных / требующих уточнения.

Политика сохранённых цитат обновляется локально до 8; версия анализа 2 прежняя. Платный повтор истории и очистка базы не запускаются. Ключи, ручные решения, заметки, очереди, модели и расписания сохраняются.
