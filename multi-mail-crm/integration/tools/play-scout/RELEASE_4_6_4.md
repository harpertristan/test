# Play Scout 4.6.4 — убрать остаток ручной очереди после очистки

В очистке 4.6.3 старый ИИ-разбор мог сохраниться по совпадению внутреннего
`app:` / `company:` ID с исключением, хотя его карточка не имела отметки
«В работе / был в работе». Такие разборы создавали дополнительные архивные
карточки и снова попадали в ручную очередь или автоисключения при нулевых
счётчиках источников.

Теперь совпадение ID само по себе не подтверждает отметку пользователя.
Очистка сохраняет карточки, реально совпадающие с правилами проектов в работе,
или явно помеченные пользователем. Разборы, кеш и комментарии остальных
исторических ID очищаются вместе с их карточками. Перед подтверждением очистки проверяется готовый список CRM: ручная очередь,
автоисключения и остальные активные карточки должны быть пусты. Если проверка
не проходит, новая база не сохраняется и команда сообщает об ошибке.
Сохранённые оригинальные
цели приложения / сайта не теряются при чтении архива; явная отметка «В работе»
всегда исключает карточку из активного списка. Название источника в интерфейсе
заменено с технического worked_archive на «Сохранено из работы».

Добавлен регрессионный пример: 54 старые карточки, из них **39 в работе,
11 на проверке и 4 автоисключения**. Исправленная очистка оставляет те же 39
карточек в работе с исходными комментариями, нулевую ручную очередь и ноль
автоисключений. Это проверка на синтетической базе, не чтение пользовательской
истории. Приложения / домены / статьи о проектах в работе остаются защищены;
отмена исключения по-прежнему возможна явным действием.

## Установка и повторная очистка

Само обновление файлы истории не очищает. Остановите приложение, обновите код,
затем один раз выполните `npm run history:clean -- --apply` (на Windows —
`npm.cmd`). Это исправленная команда. Она делает новую самостоятельную
резервную копию нынешней базы перед изменениями. Прежние копии не удаляются.
Поиск, сайты и ИИ не вызываются. Ключи, текущие фильтры, страны / юрисдикции,
реестр ориентиров, модель, профили GPU, расписания и расход API сохраняются.

Предварительный просмотр без изменений: `npm run history:clean`.
Если локальный порт занят или резервная копия не создана, очистка не выполняется.
Для отката сохраняйте согласованные код и данные из резервной копии.

После очистки смотрите результат через `npm run start:diagnostic`.
Предупреждение XProtect остаётся отдельной невыясненной проблемой;
новая версия не объявляется исправлением блокировки macOS. Поиск с повторной
блокировкой пока не возобновляйте и не обходите защиту.

«В работе» и «Исключены вручную» — пересекающиеся представления одних карточек:
например, 39 в каждой вкладке не означают 78 разных сохранённых проектов.
