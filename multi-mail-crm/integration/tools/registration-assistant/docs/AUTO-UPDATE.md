> Версия 0.2.2 исправляет Windows EPERM при переносе `node_modules`, в том числе в синхронизируемой папке OneDrive. Папка зависимостей больше не переносится: файлы сверяются и обновляются по месту. Неизменившиеся файлы не переписываются; временная блокировка файлов обрабатывается ограниченными повторами. Если не удаётся удалить временную staging-папку после успешного обновления, это не отменяет результат и не препятствует освобождению блокировки обновлятора.

# Автоматическое обновление · 0.2.1

Обновлятор сам загружает новую версию из GitHub, проверяет SHA-256 и ZIP, устанавливает зависимости во временную папку, проверяет приложение, сохраняет копию и заменяет код. Ручное копирование `data` и `.env` больше не нужно.

## Первый переход с версии 0.1 / 0.2 на Windows

1. Сохраните черновик открытой банковской анкеты.
2. В прежнем окне `Start-Windows.cmd` нажмите **Ctrl+C**. Это нужно один раз: у старой версии нет безопасного управления остановкой. Обновлятор не завершает чужие процессы.
3. Откройте **PowerShell** через меню «Пуск».
4. Скопируйте **весь блок** ниже, вставьте в PowerShell и нажмите Enter:

```powershell
$base = 'https://raw.githubusercontent.com/harpertristan/test/registration-assistant'
$release = Invoke-RestMethod "$base/updates/latest.json"
$updater = Join-Path $env:TEMP ("registration-assistant-update-" + [guid]::NewGuid().ToString('N') + '.mjs')
try {
    Invoke-WebRequest "$base/scripts/update.mjs" -UseBasicParsing -OutFile $updater
    if ((Get-FileHash $updater -Algorithm SHA256).Hash -ine $release.updater_sha256) { throw 'Updater checksum mismatch. Run the command again after checking GitHub.' }
    node --use-env-proxy $updater --start
    if ($LASTEXITCODE -ne 0) { throw 'Update did not finish. Read the message above.' }
} finally {
    Remove-Item $updater -ErrorAction SilentlyContinue
}
```

5. Если появится окно выбора папки, выберите **существующую папку помощника**, внутри которой лежит `Start-Windows.cmd`. Не папку `extension` и не пустую новую папку. Если PowerShell уже открыт в нужной папке, выбор не потребуется.
6. Дождитесь сообщения **«Обновлено до …»**. Приложение запустится автоматически. Откройте прежний адрес сервиса — обычно `http://127.0.0.1:3100`. При запуске обновлятором журнал сервера сохраняется в `.runtime/server.log`; оставлять PowerShell открытым после завершения обновления не нужно.
7. В Dolphin откройте `chrome://extensions` и нажмите кнопку перезагрузки помощника. Обновлятор сохранил расширение в прежней папке, переустанавливать его из другой папки не нужно. После сохранения черновика обновите страницу анкеты. Если подключение сбросилось — создайте и введите новый токен.

Node.js 24 LTS должен быть установлен. Пароль Windows / GitHub и API-ключ в эту команду вводить не нужно. Не отключайте проверку TLS при ошибке загрузки; проверьте доступ к GitHub и доверенные сертификаты.

## Следующие обновления

Дважды нажмите **`Update-Windows.cmd`** в установленной папке. Либо из её терминала:

```sh
npm run update -- --start
```

Начиная с 0.2.1, работающий экземпляр этой установки будет остановлен штатным локальным запросом и запущен снова после проверки. В версиях 0.1 / 0.2 сначала нужен Ctrl+C. Уже актуальная работающая версия не перезапускается без необходимости.

На macOS / Linux с прямым запуском Node.js команда та же. Для нестандартного расположения:

```sh
node /path/to/scripts/update.mjs --target /path/to/registration-assistant --start
```

`--no-start` обновляет остановленную установку без последующего запуска. Это не способ обхода проверки работающего приложения.

## Что сохраняется

- Пользователи, карточки, документы, исправления и подтверждения в папке данных.
- `.env`, `deploy/.env`, Git-метаданные и локальные файлы, не входящие в поставку программы.
- Настроенный `DATA_DIR`, включая обычную отдельную папку вне проекта.

Копия создаётся рядом с установкой: **`имя-папки-backups/дата/`**. В ней — прежний код, прежние зависимости, снимок данных и копия настроек. В этих копиях есть персональные документы и ключи из `.env`: храните их в закрытом месте, вне GitHub и общего облачного диска.

При ошибке зависимостей или проверки временной версии действующая установка не меняется. При ошибке после замены кода обновлятор возвращает прежний код, зависимости и снимок данных. На время проверки нового запуска изменения через API блокируются, чтобы откат не потерял введённые пользователями сведения.

## Если обновление не прошло

- Сообщение про старое окно: нажмите Ctrl+C в окне именно помощника и повторите команду.
- Ошибка SHA-256: файлы не устанавливаются. Проверьте источник и повторите после устранения причины; не удаляйте проверку суммы.
- Ошибка новой версии: смотрите сообщение об откате и `.runtime/server.log`. Копия не удаляется автоматически.
- Неожиданное выключение компьютера во время замены может оставить `.runtime/update-journal.json` и `update.lock`. В таком случае сначала убедитесь, что обновлятор не работает, и восстановите копию, указанную в журнале; не удаляйте блокировки вслепую. Автоматический откат при обычной ошибке и восстановление после отключения питания — разные случаи.

Обновлятор рассчитан на одну работающую копию приложения на одну базу и не обновляет Docker-контейнер изнутри. Для Docker используйте серверную процедуру: резервная копия, обновление исходников на хосте, `docker compose build app`, `docker compose up -d app`, сохраняя `.env` и тома. Отдельное обновление ОС, Node.js и Dolphin в эту команду не входит.

## Проверки

Автоматизированно проверяются целостность архива, запрет записи в настройки / данные из ZIP, пути и ссылки, сохранность пользовательских файлов, откат после неудачного запуска и штатная остановка настоящего сервера. Полный переход с ZIP 0.2.0 проверяется с настоящим `npm ci` и запуском новой версии на синтетической базе. Windows-диалог выбора папки и нативные особенности Windows / Dolphin требуют проверки на устройстве пользователя.
