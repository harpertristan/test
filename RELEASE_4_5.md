# Play Scout 4.5.0 — очередь Google Play и параллельный ИИ

## Google Play и CRM

- Первые полученные страницы поиска сразу передают ID в проверку, не дожидаясь всей пагинации. Рекомендации и дополнительный индекс работают рядом с очередью карточек.
- Исправлены потеря уведомления о новой партии и гонка при сохранении очереди: карточка больше не помечается поставленной в очередь раньше, чем действительно попала в неё.
- Три сбоя поисковых запросов приостанавливают новые запросы; полученные карточки продолжают проверяться. Отказ доступа / ограничение Google останавливает обращения и сохраняет очередь. Есть отдельная кнопка «Продолжить карточки Google Play» с количеством оставшихся.
- Тяжёлые расчёты общей базы, карточки и выгрузки вынесены в отдельный поток. Одновременные чтения используют один снимок. Изменение исключений или комментария обновляет снимок; одни счётчики запросов не вызывают повторный разбор всей базы.
- После трёх последовательных сетевых / нечитаемых ответов Brave источник приостанавливается, сохраняя полученное. Не выполняются сотни одинаково неудачных запросов подряд. Это обработка сбоя, а не количественная квота.

## Вся вкладка «Проверить вручную»

Вверху CRM появилась кнопка **«Все карточки на проверке → сайты + ИИ»** с количеством записей. Она берёт **всю** ручную вкладку, включая записи за пределами первых 50 строк и текущего фильтра. Читает актуальные публичные страницы сайтов и, при наличии приложения, пробует обновить описание через адаптер Google Play; после трёх сбоев этого обновления продолжает сайты без повторения неудачных обращений для каждой карточки; выполняет ИИ-разбор в выбранном объёме. Если источник недоступен, это указано в карточке — сохранённый текст не выдаётся за свежий.

Если сохранено только название, по Brave ищется кандидат сайта: проверяются совпадение имени в домене и тексте страницы, исключаются публикации и посторонние сервисы. Неоднозначная ссылка не считается установленным сайтом. Без доступного источника карточка остаётся незавершённой. Исправлено ручное исключение записей, у которых ещё нет ссылки: оно сопоставляется по названию.

Ручные исключения, «Уже в работе / был в работе» и подтверждённые вами записи не отправляются. Успешные ответы, оригиналы, цитаты, модель и дата сохраняются по мере готовности. После остановки, сбоя или перезапуска используйте **«Продолжить полную проверку»**: уже успешно разобранные в этом проходе записи повторно не отправляются. Поздние ручные исключения также учитываются.

Повторное нажатие основной кнопки начинает **новый полный проход**. Облачные разборы оплачиваются из API-баланса. Кнопка «Всю базу на повторную проверку» по-прежнему только меняет ручные категории без вызова API. Обновление 4.4 → 4.5 само не сбрасывает вашу базу и не запускает платный разбор. При переходе с версии до 4.4 действует ранее запрошенный разовый возврат базы на ручную проверку.

ИИ не ставит «Подтверждено мной». Даже после разбора сомнительные записи остаются доступны в ручной вкладке; решение подтверждаете вы.

## GPT + Ollama

В настройках «Где выполнять анализ» выберите **«GPT + Ollama · общая очередь параллельно»**, сохраните. Введите установленную модель Ollama и отдельно проверьте локальный ИИ и облачный ИИ кнопками. Облачный тест использует один платный запрос OpenAI; локальный тест не вызывает OpenAI.

По умолчанию до трёх облачных карточек и одна локальная обрабатываются одновременно. Параллельность OpenAI задаётся в настройках. Освободившийся обработчик берёт следующую карточку; одна карточка не проверяется двумя моделями. Это увеличивает пропускную способность очереди. Повторная оценка одной карточки двумя моделями для сверки не включается.

Расход OpenAI и локальной модели учитывается раздельно. У каждой карточки записаны действительный движок и модель. Сбой Ollama останавливает её обработчик; GPT продолжает оставшуюся очередь. При отказе доступа / квоте облака или трёх сбоях подряд облачный обработчик останавливается; локальный может продолжать. Неуспешные карточки остаются для продолжения. Неполные ответы не сохраняются как подтверждённые факты.

Два ИИ не снимают ограничения Google Play / Brave и не делают сами поисковые API быстрее. Ollama не платит OpenAI за локально обработанные карточки; OpenAI может забрать большую часть очереди, если быстрее локальной модели. Новых количественных квот не добавлено.
