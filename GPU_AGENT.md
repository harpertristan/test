# Локальный GPU-агент: Windows, Mac M5 и 6 × RTX 2060 Super

В версии 4.2 поиск по источникам и ИИ-разбор — отдельные процессы. Google Play, сайты, публикации и реестры складывают находки в одну CRM. Агент читает публичные страницы продукта, выбирает доказательства, проверяет бизнес-счёт, страну IBAN, формат работы через партнёра и наличие веб-кабинета. Исключения действуют до обращения к ИИ и перед сохранением результата.

**llama.cpp — дополнительный движок, Ollama остаётся доступной.** Смена оболочки сама по себе не гарантирует ускорения: важнее GPU, модель, размер материалов, длина ответа и параллельность. Новый движок получает короткие фрагменты, возвращает номера дословных цитат и структурированный JSON. Программа разворачивает цитаты в оригиналы и проверяет их прежними правилами. Недоказанное остаётся неизвестным. Программа не входит в личные кабинеты и не создаёт банковские аккаунты.

## Что выбрать для ваших компьютеров

| Компьютер | Начальный вариант | Параллельность |
|---|---|---|
| Windows, RAM 32 ГБ, NVIDIA 8 ГБ | Qwen2.5-3B-Instruct GGUF Q4_K_M; сравнить с 7B Q4_K_M на тех же карточках | Один GPU-сервер, одна карточка за раз |
| Mac M5, 16 ГБ общей памяти | Qwen2.5-3B-Instruct GGUF Q4_K_M, Metal | Один сервер, одна карточка; оставить память macOS и браузеру |
| Один компьютер, 6 × RTX 2060 Super 8 ГБ | По копии Qwen2.5-7B-Instruct Q4_K_M на каждой карте; 3B для сравнения скорости | Шесть серверов, до шести разных карточек одновременно |

Начните с экономного режима. Подробный разбор одной карточки отправляет больше текста и может не поместиться в контекст сервера 4096: для него отдельно увеличивают `--ctx-size` и проверяют VRAM. Установленный launcher предназначен для экономного режима; он не увеличивает память автоматически. 32 ГБ RAM Windows не заменяют VRAM. На Mac 16 ГБ делятся между системой, GPU и приложениями.

Не ставлю модель «самой качественной» по размеру: 7B следует сравнить с 3B по вашим подходящим и неподходящим примерам. Более крупная модель может точнее понимать текст, но не заменяет сведения на сайте.

## Windows: одна карта

1. Обновите Play Scout по [инструкции 4.2 для Windows](RELEASE_4_2_WINDOWS.md). Оставьте существующие `.env` и `data` на месте.
2. Установите актуальный драйвер NVIDIA. В PowerShell выполните `nvidia-smi`: должна отображаться ваша карта и свободная VRAM. Если драйвер требует перезагрузки, выполните её до запуска серверов.
3. На [официальной странице релизов llama.cpp](https://github.com/ggml-org/llama.cpp/releases) скачайте Windows x64 CUDA-сборку и соответствующие CUDA-библиотеки из того же релиза, если они вынесены отдельно. Распакуйте их в **`C:\AI\llama`**. Там должен находиться `llama-server.exe` и поставляемые с ним DLL. Сборка CPU / Vulkan — другой вариант; в этой инструкции используется CUDA. Если CUDA-сборка больше не поддерживает вашу карту, выберите совместимый релиз; номер CUDA сам по себе не гарантирует поддержку GPU.
4. С официальной страницы [Qwen2.5-3B-Instruct-GGUF](https://huggingface.co/Qwen/Qwen2.5-3B-Instruct-GGUF/tree/main) скачайте вариант **Q4_K_M** в **`C:\AI\models`**. Полный файл назовите **`qwen2.5-3b-instruct-q4_k_m.gguf`**. Если модель опубликована частями `00001-of-...`, скачайте все части и объедините утилитой `llama-gguf-split --merge` из той же сборки; переименование одной части не создаёт полную модель. Не выбирайте 16-битные веса для 8 ГБ VRAM.
5. В новом PowerShell запустите:

```powershell
cd "$env:USERPROFILE\PlayScout"
node .\scripts\start-gpu-agent.js --server "C:\AI\llama\llama-server.exe" --model "C:\AI\models\qwen2.5-3b-instruct-q4_k_m.gguf"
```

Оставьте это окно открытым. Сервер слушает только `127.0.0.1:8081`; запуск может сначала загружать веса. В его журнале проверьте загрузку слоёв на CUDA. Команда не скачивает модель сама.

6. В другом окне PowerShell запустите CRM:

```powershell
cd "$env:USERPROFILE\PlayScout"
npm.cmd run start:desktop
```

7. В CRM → «Настройки источников, ИИ и ежедневного поиска» → профиль **Windows · 32 ГБ RAM / NVIDIA 8 ГБ** → **«Применить профиль ИИ»**. Нажмите **«Проверить локальный ИИ / все GPU»**. Alias модели должен совпасть: `qwen2.5-3b-instruct-q4_k_m`.
8. Разберите одну карточку. Проверьте время и вывод через `nvidia-smi`. Если слои остались на CPU, сначала исправьте CUDA / VRAM, а не увеличивайте параллельность.

Профиль не запускает поиск и не скачивает веса. При ошибке локального сервера платный OpenAI / Gemini автоматически не вызывается.

## Mac M5, 16 ГБ

1. Обновите существующую папку по [инструкции Mac](RELEASE_4_2_MAC.md).
2. Скачайте macOS arm64 / Metal-сборку [llama.cpp](https://github.com/ggml-org/llama.cpp/releases) и распакуйте её в **`~/AI/llama`**. В этой папке должны лежать `llama-server` и библиотеки сборки. Если бинарник находится в подпапке, используйте его фактический путь.
3. Скачайте тот же полный GGUF **Qwen2.5-3B-Instruct Q4_K_M** в **`~/AI/models/qwen2.5-3b-instruct-q4_k_m.gguf`**. Для файлов из нескольких частей см. пояснение выше. При предупреждении macOS об источнике приложения проверьте, что сборка взята с официального релиза, и разрешите её в «Настройки системы → Конфиденциальность и безопасность».
4. В новом Терминале:

```bash
cd "$HOME/Desktop/play-scout-v31" &&
node ./scripts/start-gpu-agent.js --server "$HOME/AI/llama/llama-server" --model "$HOME/AI/models/qwen2.5-3b-instruct-q4_k_m.gguf"
```

Launcher выбирает один процесс Metal, без CUDA. В журнале проверьте использование Metal. Остановите ненужную загруженную модель Ollama, чтобы она не занимала общую память: `ollama ps`, затем `ollama stop ИМЯ_МОДЕЛИ`. Само приложение Ollama удалять не требуется.

5. В другом Терминале запустите CRM:

```bash
cd "$HOME/Desktop/play-scout-v31" &&
bash ./2-Запустить.command
```

6. В CRM примените профиль **Mac M5 · 16 ГБ**, проверьте локальный ИИ и разберите одну карточку. Профиль остаётся экономным; увеличение контекста и запуск нескольких копий модели при 16 ГБ могут ухудшить скорость из-за нехватки памяти.

## Ферма: шесть RTX 2060 Super в одном компьютере

Рекомендую **шесть независимых реплик модели**, по одной на каждой карте. Это ускоряет очередь из разных проектов. Одна карточка разбирается одной картой; шесть карт сами по себе не ускоряют её в шесть раз. Одинаковая модель даёт тот же класс качества, независимо от числа реплик.

Нужны:

- плата / BIOS / ОС, которые определяют все шесть карт; проверьте список `nvidia-smi`;
- достаточное питание, охлаждение и запас RAM / SSD; при нехватке RAM 32 ГБ могут оказаться узким местом для шести процессов;
- совместимый драйвер NVIDIA и CUDA-сборка llama.cpp;
- полный GGUF; один файл на диске можно использовать во всех шести процессах;
- Play Scout 4.2. Отдельные Kubernetes, Docker или распределённое обучение для этого сценария не нужны.

Майнинговые USB-riser / PCIe x1 могут замедлять загрузку и обмен. Для одной большой модели, разделённой между картами, пропускная способность шин особенно важна. 6 × 8 ГБ — это 48 ГБ отдельных банков памяти. llama.cpp умеет распределять слои одной модели между GPU, но такой режим требует отдельного подбора модели, контекста и измерений; в готовом launcher выбран режим реплик.

Скачайте [Qwen2.5-7B-Instruct-GGUF Q4_K_M](https://huggingface.co/Qwen/Qwen2.5-7B-Instruct-GGUF/tree/main), подготовьте полный файл **`C:\AI\models\qwen2.5-7b-instruct-q4_k_m.gguf`**, затем:

```powershell
cd "$env:USERPROFILE\PlayScout"
node .\scripts\start-gpu-agent.js --server "C:\AI\llama\llama-server.exe" --model "C:\AI\models\qwen2.5-7b-instruct-q4_k_m.gguf" --gpus 0,1,2,3,4,5 --threads 2
```

Для каждого процесса выставляется свой `CUDA_VISIBLE_DEVICES`, один слот и контекст 4096. Модели загружаются последовательно, чтобы уменьшить пик расхода RAM; после готовности карточки разбираются параллельно. Адреса: `http://127.0.0.1:8081` … `http://127.0.0.1:8086`. В CRM примените профиль **6 × RTX 2060 Super** и проверьте все шесть обработчиков. Если ОС нумерует карты иначе, скорректируйте `--gpus`. При ошибке процесса launcher завершает пул; прочитайте журнал, устраните причину и запустите снова.

Если CRM остаётся на другом компьютере, `127.0.0.1` там указывает на него самого. Готовый launcher намеренно слушает только локальный интерфейс. Для доступа с Mac к ферме настройте защищённую сеть / VPN или аутентифицированный reverse proxy и укажите реальные адреса в CRM. Не публикуйте необработанный порт llama.cpp в интернет. Необязательный `LOCAL_AI_API_KEY` в `.env` CRM передаётся только вашим настроенным GPU-серверам; сервер / proxy должен быть настроен на тот же ключ.

## Насколько быстрее и качественнее

Для **ИИ-части очереди**, одинаковой модели и шести свободных GPU верхняя идеальная оценка — около шестикратной пропускной способности. Это не измерение и не обещание. Чтение сайтов, ограничения Google / Brave, запись базы, CPU и шины уменьшают выигрыш. Ускорение всей операции можно оценить как `1 / ((1 − p) + p / 6)`, где `p` — доля времени, которую раньше занимало именно вычисление ИИ. При `p = 0,8` идеальный предел всей операции — около 3×; при `p = 0,5` — около 1,7×. Смена 3B на 7B делает такое сравнение неравным: сначала сравните одну и шесть карт с одной моделью.

Качество не растёт от добавления одинаковых копий. Ферма позволяет проверить больше карточек за время или применить более тщательную модель к сомнительным записям. Сайты без прямого подтверждения EU IBAN по-прежнему остаются на проверке.

## Проверить на своих видеокартах

Короткий тест использует пять встроенных синтетических примеров и только локальные серверы. Он выводит время, решение и совпадение с ожидаемым; это не полноценная оценка банковского поиска.

Одна карта / Mac:

```bash
node scripts/benchmark-local-agent.js --endpoints http://127.0.0.1:8081 --model qwen2.5-3b-instruct-q4_k_m
```

Ферма:

```powershell
node .\scripts\benchmark-local-agent.js --endpoints http://127.0.0.1:8081,http://127.0.0.1:8082,http://127.0.0.1:8083,http://127.0.0.1:8084,http://127.0.0.1:8085,http://127.0.0.1:8086 --model qwen2.5-7b-instruct-q4_k_m
```

Выполняйте из папки PlayScout и при остановленном разборе CRM, чтобы два клиента не спорили за один GPU. Для сопоставимого замера нужны одинаковые модель и карточки, прогрев модели и несколько повторов. Пять примеров не заполняют шесть GPU полностью; для измерения пропускной способности используйте достаточную реальную очередь. Ключи облачных API для теста не используются.

Меняя фактический GGUF, меняйте `--alias` и имя модели в CRM: модельное имя участвует в кэше. Не выдавайте разные модели за одинаковый alias на разных обработчиках.

Официальная документация: [llama-server и JSON Schema](https://github.com/ggml-org/llama.cpp/blob/master/tools/server/README.md), [CUDA / Metal и сборка](https://github.com/ggml-org/llama.cpp/blob/master/docs/build.md), [релизы](https://github.com/ggml-org/llama.cpp/releases). Аппаратная скорость на вашем M5 и RTX 2060 Super здесь не измерялась.
