# Facebook, LinkedIn и реклама — подключение в 4.8

Для чужих публичных публикаций и рекламы добавлен **API Apify**. Собственное приложение Meta / LinkedIn и их одобрение для этого подключения не требуются. Данные собирает выбранный вами сборщик Apify; его покрытие, доступность и цена зависят от задачи. Это API Apify, а не официальный глобальный поиск Meta / LinkedIn.

Прежние источники Facebook / LinkedIn через Brave сохранены отдельно. Они ищут индексируемые страницы и не получают доступ к аккаунту соцсети. Пустая выдача и экран входа не считаются подтверждённой доступностью полного текста.

## 1. Аккаунт и сохранённые задачи

1. Зарегистрируйтесь на [console.apify.com](https://console.apify.com/). В настройках найдите API token. Пока не запускайте сбор.
2. В [Apify Store](https://apify.com/store) найдите сборщик публичной рекламы / поиска Facebook и сборщик публичного поиска LinkedIn. Проверьте тариф, требования и пример результатов. Выбирайте сборщики без вашего логина, cookies или `li_at`.
3. Создайте **сохранённую задачу / Actor Task** для нужного сборщика. Для поиска новых сервисов задайте, например, `business account`, `corporate account`, `IBAN`. Сборщик, принимающий только URL известных компаний, предназначен для наблюдения за ними и не заменяет поиск новых компаний по ключевым словам.
4. Для первого теста оставьте **один URL или один поисковый запрос** и явно задайте **1–20 результатов**. Лимит на каждый из многих профилей не ограничивает общий объём. Проверяются поля `resultsLimit`, `maxPosts`, `maxItems`, `maxResults`, `maxPostsPerProfile`, `maxPostsPerPage`, `limit`. Неограниченная задача или неизвестное поле ограничения не запускается: потребуется подходящая настройка / адаптация сборщика.
5. Сохраните задачу и скопируйте её **Task ID**, а не Actor ID. Также подходит `username~saved-task-name`. Для Facebook и LinkedIn используются отдельные задачи; можно начать с одной.
6. В Apify проверьте ограничения расходов и автопополнение. Бесплатный стартовый баланс, аренда акторов и цена результатов зависят от аккаунта и сборщика.

Запросы, страны и URL задаются **в сохранённой задаче Apify**. Поля Brave в CRM не переписывают её ввод. Доставка рекламы пользователям ЕС сама по себе не подтверждает регистрацию рекламодателя в ЕС или выдачу бизнесу EU IBAN.

## 2. Ключ вводится локально

После обновления остановите программу и выполните в рабочей папке:

```sh
npm run configure:social-api
```

Windows: `npm.cmd run configure:social-api`.

Команда спросит API token и Task ID Facebook / LinkedIn. Ввод скрыт, значения сохраняются в локальный `.env`; пустой ответ сохраняет прежнее значение. Ключ не отправляется в чат и не вводится в общую веб-страницу. Конфигуратор ничего не собирает и не очищает историю.

Перезапустите `npm run start:manual`. В настройках появятся признаки заданных ключа и задач; они ещё не означают успешной проверки доступа.

## 3. Проверка и первый небольшой сбор

1. «Новый поиск» → **«Соцсети через Apify API»** → выберите одну задачу.
2. **«Проверить доступ»** читает задачу и её ввод. Актор / платный сбор не запускается. Видны ошибки ключа, доступа, лимита ввода или требования логина.
3. **«Запустить выбранные … платный Apify»** создаёт один запуск сохранённой задачи на источник, без автоматического повтора. Можно оставить «ИИ после сбора» выключенным и сначала посмотреть находки.
4. Передаются `timeout=120`, `maxItems=20`, `maxTotalChargeUsd=1`. Читаются не более 20 строк результатов. Денежный параметр **не гарантирует общую цену любого актора**: аренда, вычисления и тарификация результатов могут учитываться отдельно. Проверьте ограничения в Apify.
5. В строке источника есть ссылка на запуск / журнал. Сумма показывается, если API вернул `usageTotalUsd`; неизвестная сумма не считается нулём. Ежедневные запуски Apify в этой версии отключены.

«Остановить всё» посылает отмену удалённой задаче; выполненная работа может быть платной. Если отмена не подтверждена или ответ запуска потерян, проверьте Runs в Apify перед повтором. Потерянный HTTP-ответ не приводит к автоматическому повторному платному запуску.

## Формат и качество результатов

Поддерживаются распространённые поля URL (`url`, `postUrl`, `post_url`, `permalink`, `adSnapshotUrl`) и текста (`text`, `postText`, `message`, `caption`, `ad_creative_bodies`, `snapshot.body.text`). Для рекламы поддерживается публичная ссылка по `adArchiveID` / `adId`. Неизвестный формат показывает `APIFY_SCHEMA`, после чего нужна адаптация конкретного сборщика.

Находки проходят общие правила приёма, объединение провайдера и защиту известных проектов. Явный мусор виден в «Отсеяно». Имя рекламодателя может использоваться для поиска его сайта, но бизнес-счёт и EU IBAN подтверждаются по прочитанным источникам. Ответы актора рассматриваются как данные, а не инструкции.

## Официальные API

Meta Pages и LinkedIn Community Management / Posts требуют приложений, токенов, ролей и разрешений. Личный аккаунт не даёт глобальный поиск чужих постов. Для Meta Ads Library API действуют отдельные требования доступа и покрытия. Этот выпуск не обещает получение такого доступа и не включает OAuth управляемых страниц.

Справки: [Meta Pages](https://developers.facebook.com/docs/pages-api/), [Meta Ads Library](https://www.facebook.com/ads/library/api/), [LinkedIn](https://learn.microsoft.com/en-us/linkedin/marketing/community-management/community-management-overview), [Apify API](https://docs.apify.com/api/v2).

Для известных открытых страниц и RSS остаётся наблюдение без Apify. YouTube: `https://www.youtube.com/feeds/videos.xml?channel_id=ID_КАНАЛА`.
