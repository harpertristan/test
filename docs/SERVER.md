# Развёртывание на сервере: Windows у пользователя, Linux на сервере

Пользователю нужен только Dolphin и расширение. Документы, OCR, база и API работают на сервере. Здесь приведён вариант Ubuntu 24.04 LTS + Docker + Caddy; общедоступный сервер автоматически не создан.

Для установки нужен администратор с SSH-доступом. Подготовка DNS и Linux — разовая техническая работа; ежедневное использование описано отдельно в WINDOWS-DOLPHIN.md. Не передавайте пароли сервера и API-ключи в чат.

## 1. Что заказать

- Один сервер Ubuntu 24.04 LTS: ориентир 4 vCPU, 8 ГБ RAM, SSD от 40 ГБ, без GPU.
- Постоянный IPv4-адрес.
- Домен или поддомен, например `assistant.your-company.com`.
- Шифрование диска и закрытое резервное хранилище у хостера.

До оплаты проверьте, что расширение устанавливается в вашей версии Dolphin. Выберите подходящий для корпоративных документов регион хранения. Оценка стоимости — в MODELS.md; актуальный тариф хостера отдельно не проверен.

## 2. Настройте домен

В панели регистратора / DNS создайте запись типа **A**: имя `assistant`, значение — IPv4 вашего сервера. Пример: если основной домен `your-company.com`, получится `assistant.your-company.com`.

Дождитесь, когда запись начнёт указывать на сервер. Неверная DNS-запись помешает получить HTTPS-сертификат.

## 3. Подключитесь из Windows

В меню «Пуск» найдите **PowerShell**. Выполните, заменив `SERVER_IP` адресом сервера:

```powershell
ssh root@SERVER_IP
```

Проверьте SSH fingerprint по панели хостера перед первым подтверждением. Введите пароль, предоставленный хостером, или используйте свой SSH-ключ. Далее команды выполняются в окне подключения к Linux-серверу.

## 4. Установите Docker

Для чистой Ubuntu 24.04:

```sh
apt-get update
apt-get install -y docker.io docker-compose-v2 unzip
systemctl enable --now docker
docker version
docker compose version
```

Не продолжайте, если последние команды завершаются ошибкой. Эти инструкции не требуют скачивать и запускать неизвестный shell-скрипт. Для другой ОС используйте официальную инструкцию Docker именно для этой ОС.

В сетевом экране хостера разрешите входящие TCP **80 и 443**, а SSH / **22** ограничьте IP администратора, если возможно. Порт 3100 наружу не открывайте. Для установки нужны HTTPS-доступ к Docker Hub и npm; для сертификатов — к сервису ACME, для необязательного ИИ — `api.openai.com`.

## 5. Передайте архив проекта

Скачайте `registration-assistant-0.2.2.zip` на Windows. В **новом локальном** окне PowerShell передайте файл, указав настоящий путь:

```powershell
scp "C:\Users\YOUR_NAME\Downloads\registration-assistant-0.2.2.zip" root@SERVER_IP:/root/
```

Вернитесь в окно SSH и выполните:

```sh
mkdir -p /opt
unzip /root/registration-assistant-0.2.2.zip -d /opt
cd /opt/registration-assistant/deploy
cp .env.example .env
chmod 600 .env
nano .env
```

Вместо `assistant.example.com` впишите **свой** домен. Для первого запуска оставьте поля API пустыми: загрузка, OCR, проверенные данные и вставка работают без ИИ.

Сохранение в nano: **Ctrl+O**, **Enter**, выход **Ctrl+X**. Не вставляйте реальные значения в примеры или отчёты.

## 6. Соберите приложение и создайте пользователей

Находясь в `/opt/registration-assistant/deploy`:

```sh
docker compose build
docker compose run --rm --no-deps app node scripts/create-user.js
```

Придумайте логин латиницей и пароль от 14 символов. Пароль вводится скрыто, затем вводится повторно. Для второго и третьего пользователей повторите только вторую команду. У каждого пользователя отдельные карточки.

## 7. Запустите и проверьте

```sh
docker compose up -d
docker compose ps
docker compose logs --tail=40 app caddy
```

Ожидается: приложение работает / healthy; Caddy получает сертификат. Откройте **свой HTTPS-адрес** в браузере. Не обходите предупреждение о недействительном сертификате: проверьте DNS, открытые 80/443 и журнал Caddy.

Проверьте рабочий сценарий на вымышленных данных:

1. Войдите.
2. Создайте компанию `Example Limited`.
3. Добавьте заметку с текстом `Company name: Example Limited`.
4. Проверьте автоматически извлечённое значение `Example Limited`, отметьте общую галочку подтверждения итоговых данных и нажмите кнопку подтверждения.
5. Подключите расширение по WINDOWS-DOLPHIN.md.
6. На черновой / тестовой форме проверьте вставку и сохранение исправления.
7. Только после этого переходите к настоящим документам и анкетам.

## 8. Как остановить, запустить и посмотреть состояние

Все команды — из `/opt/registration-assistant/deploy`:

```sh
docker compose stop
docker compose up -d
docker compose ps
```

Остановка сохраняет данные. **Не используйте `docker compose down -v`: флаг `-v` удаляет тома с документами и базой.**

Данные приложения находятся в именованном Docker-томе `assistant_data`. Ключи и настройки — в `deploy/.env`; сертификаты — в отдельных томах Caddy. Процессы запускаются заново при перезапуске контейнера.

## 9. Резервная копия

Остановите приложение на время копирования; веб-интерфейс временно будет недоступен:

```sh
cd /opt/registration-assistant/deploy
mkdir -p /root/assistant-backups
chmod 700 /root/assistant-backups
docker compose stop app
docker compose run --rm --no-deps --user root -v /root/assistant-backups:/backups app node scripts/backup.js /backups --server-stopped
docker compose up -d app
```

Скрипт создаёт отдельную согласованную копию SQLite и оригиналов. Сам архив не зашифрован: храните его в зашифрованном закрытом хранилище и регулярно переносите за пределы сервера. `.env` сохраните отдельно в защищённом хранилище. В интерфейсе нет автоматического расписания резервных копий; настройте ежедневное выполнение у администратора / хостера и срок удаления, например 14 дней.

### Восстановление

Сначала проверьте восстановление на тестовом сервере. Для рабочего восстановления остановите `app`, сохраните текущие данные отдельной копией и выберите каталог из `/root/assistant-backups`.

Запустите контейнер обслуживания:

```sh
docker compose run --rm --no-deps --user root -v /root/assistant-backups:/backups --entrypoint sh app
```

В нём замените `BACKUP_FOLDER` точным именем выбранной копии:

```sh
test -f /backups/BACKUP_FOLDER/assistant.sqlite
```

Продолжайте только если проверка успешна. Следующие команды заменяют действующие данные; текущая копия должна быть сохранена заранее:

```sh
rm -f /app/data/assistant.sqlite /app/data/assistant.sqlite-wal /app/data/assistant.sqlite-shm
rm -rf /app/data/uploads
cp /backups/BACKUP_FOLDER/assistant.sqlite /app/data/assistant.sqlite
cp -a /backups/BACKUP_FOLDER/uploads /app/data/uploads
chown -R node:node /app/data
exit
```

Затем `docker compose up -d app`. Восстановленная база содержит прежние сессии / токены; отзовите токены через веб-интерфейс и создайте новые. Проверьте вход, карточку, оригиналы и вставку тестового значения.

## 10. Подключение модели

Следуйте MODELS.md. После изменения `.env` пересоздайте контейнер `app`. Лимит запросов приложения не заменяет денежный лимит в кабинете API.

## Что проверено и что остаётся

Проверки в облаке записаны в VALIDATION.md. Наличие Dockerfile не означает, что публичный домен, HTTPS и сервер уже созданы. Проверку Dolphin на Windows и macOS, доступ с пользовательских компьютеров и выбранную API-модель нужно выполнить отдельно после установки.
