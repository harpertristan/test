# Обновление до 0.2.0: форма блокнота, сопоставление источников и общее подтверждение

Персональные документы из чата в проект, ZIP и GitHub **не включены**. Проверки используют вымышленные сведения.

## Если приложение работает на Windows

1. Сохраните черновик открытой банковской анкеты: при обновлении расширения страницу потребуется обновить.
2. В окне запущенного приложения нажмите **Ctrl+C**, чтобы остановить его.
3. Сделайте копию прежней папки проекта целиком в отдельное безопасное место. Особенно важны **`data`** и **`.env`**, если он есть: это пользователи, документы, база и настройки.
4. Скачайте `registration-assistant-0.2.0.zip` и распакуйте его в новую папку.
5. Скопируйте из старой установки папку **`data`** и файл **`.env`** в корень новой папки, рядом с `server.js`. Если после распаковки вы уже запускали новый экземпляр и там есть свои данные, сначала сохраните их отдельно; не заменяйте их вслепую.
6. Запустите **`Update-Windows.cmd`** из новой папки. Он установит зависимости, не создавая пользователей заново.
7. Запустите **`Start-Windows.cmd`**, откройте `http://127.0.0.1:3100` и войдите под прежним пользователем.
8. В Dolphin откройте `chrome://extensions`. Удалите старое расширение и загрузите папку **`extension` из новой версии**. Если обновляете файлы в прежней папке, вместо переустановки можно нажать кнопку перезагрузки расширения.
9. Создайте новый токен в веб-интерфейсе и подключите расширение. Обновите страницу анкеты после сохранения её черновика.

Если приложение сообщает, что пользователей нет, остановите его и проверьте, что прежняя `data` скопирована именно рядом с `server.js`, а в `.env` не указан другой `DATA_DIR`. Не создавайте новую пустую базу вместо существующей.

## Если приложение работает в Docker на сервере

1. Создайте резервную копию по SERVER.md.
2. Остановите приложение: `docker compose stop app` из прежней папки `deploy`.
3. Обновите исходники в том же каталоге проекта, сохранив **`deploy/.env`**, именованные Docker-тома и прежнее имя Compose-проекта.
4. Выполните из `deploy`:

```sh
docker compose build app
docker compose up -d app
docker compose ps
```

5. Обновите расширение в Dolphin и переподключите его новым токеном.

Не используйте `docker compose down -v`: это удалит тома с данными.

## Новый порядок работы

1. Выберите компанию с названием, соответствующим документам. Допустимо короткое начало названия; чужая компания не должна смешиваться с выбранной.
2. Раскройте **«Заполнить форму и создать блокнот»**. Введите сведения в подписанные поля. Имя и фамилию указывайте отдельно, как в документе латиницей. Можно взять текущие итоговые данные одной кнопкой.
3. Нажмите **«Сохранить и сопоставить с документами»**. Кнопки скачивания позволяют получить заполненный TXT или пустой шаблон. Готовый пустой файл также находится в `templates/company-info-template.txt`.
4. Загрузите документы и существующий блокнот. Понятные сведения извлекаются автоматически; старые документы можно обработать кнопкой **«Разобрать все документы заново»**.
5. Смотрите итоговые значения. При совпадении нескольких источников доступно раскрытие **«Совпадает в источниках»**. При расхождении показываются варианты и их цитаты; выберите правильный или исключите неверный. Ненужный источник можно удалить в разделе ручного просмотра документов.
6. Для сложного текста доступен необязательный разбор через настроенный API. Кнопка предупреждает об отправке текста документов, включая персональные сведения, OpenAI. Обычный разбор не использует API.
7. Проверьте итоговую карточку. Отметьте **«Я проверил(а) все итоговые данные…»** и нажмите **«Подтвердить итоговые данные»**. Если есть неразрешённые расхождения, подтверждение недоступно.
8. В Dolphin выберите ту же компанию. Для обычных `First name / Last name` по умолчанию используется **контактное лицо из блокнота**. Директора и бенефициара можно выбрать отдельно, когда их роль явно указана в источниках.
9. Нажмите **«Заполнить найденные пустые поля»** или включите **«Автоматически заполнять новые пустые поля»**. Заполненные поля не заменяются этим режимом. Согласия, пароли и отправка анкеты остаются за вами.

После любого нового документа, изменения источника или итогового значения общее подтверждение перестаёт действовать. Нужно проверить обновлённую карточку и подтвердить её снова. Расширение проверяет актуальность перед вставкой и обновляет статус открытой панели.

## Что именно стало распознаваться

- `Website`, `Web site`, `Website URL`, `Company URL`, `Site` → «Сайт компании».
- `First name`, `Given name`, `Forename`, `first_name`, `firstName` → имя выбранного контактного лица.
- `Last name`, `Surname`, `Family name`, `last_name`, `lastName` → фамилия.
- Рабочий email, телефон, международный код и национальная часть; страна регистрации и её варианты `UK / GB / United Kingdom`.
- Описание бизнеса, краткое сообщение и назначение счёта, когда они есть в источнике. Оборот не подменяет объём операций.
- Даты в точечном, ISO и английском текстовом формате приводятся к ISO; формат вставки может учитывать явно заданный образец поля.

Двухчастное латинское имя без подписей в обычном блокноте разбирается как «имя → фамилия» с пояснением. Это предположение обязательно проверяется оператором в итоговой карточке. Составные и неоднозначные имена не делятся наугад. Адрес проживания не доказывает гражданство, а страна регистрации — налоговое резидентство. Наличие цитаты не доказывает подлинность документа.

Поддержать все сайты и все формулировки заранее невозможно. Непонятное поле остаётся без автоподстановки. iframe, закрытый Shadow DOM, canvas и нативные приложения по-прежнему требуют отдельной поддержки.
