# Запуск без включённого компьютера

Программа должна работать на постоянно включённом облачном сервере. Вы заходите на сайт с компьютера или телефона, а сервер сам выполняет поиск по расписанию. Браузер можно закрывать.

Ниже готовый вариант для Render. Потребуются ваш аккаунт Render, GitHub и платный веб-сервис с постоянным диском. Текущую стоимость сервиса и диска проверьте в Render перед созданием. Бесплатный засыпающий сервис не обеспечивает ежедневный поиск и сохранность истории.

Исходники этого проекта уже загружены в [harpertristan/test](https://github.com/harpertristan/test). Для него можно сразу перейти к шагу 3 ниже.

## Если аккаунтов и опыта пока нет

1. Скачайте свежий архив приложения и распакуйте его. Откройте папку с `package.json`, `Dockerfile` и `render.yaml`.
2. Создайте аккаунт на https://github.com и новый пустой репозиторий, например `play-scout`. Можно использовать существующий `harpertristan/test`, если это ваш репозиторий. Найдите загрузку файлов: **uploading an existing file** в пустом репозитории или **Add file → Upload files** в существующем. Загрузите в корень файлы приложения и папки `lib`, `public`, `test`, `scripts`. Файл `render.yaml` должен лежать в корне, а не во вложенной папке `play-scout`. Не загружайте `node_modules`, файлы с паролями (`.env`, `*.env`) или папку `data` с личной историей. Подтвердите загрузку кнопкой **Commit changes**.
3. Создайте аккаунт на https://render.com и подключите GitHub. Выберите создание **Blueprint** из вашего репозитория. Названия пунктов могут отличаться в интерфейсе хостинга.
4. Render прочитает `render.yaml`. До подтверждения создания проверьте платный план, регион Frankfurt, одну копию сервиса и постоянный диск на 1 ГБ с путём `/var/data`. Диск обязателен: он хранит историю приложений и расписание.
5. Подтвердите создание и дождитесь успешного развёртывания. В карточке сервиса появится его HTTPS-адрес. Это и будет ваша ссылка на приложение.
6. В настройках переменных окружения сервиса найдите автоматически созданный **APP_PASSWORD**. Это пароль входа: смотрите его только в своём аккаунте хостинга, не публикуйте и не присылайте в чат. Откройте HTTPS-адрес приложения и в окне входа укажите логин **admin** и этот пароль.
7. В блоке «Ежедневный поиск» проверьте время и нажмите «Сохранить расписание». По умолчанию — 09:00 по Калининграду (UTC+2). В версии 2.3 профиль настроен под ваши примеры: бизнес-счета / EMI / платёжные платформы, 12 месяцев, порог установок 0. При необходимости измените его в форме. Первый пропущенный запуск начнётся при запуске сервера; это нормальное поведение.

После этого компьютер и браузер можно выключать. Сервер должен оставаться включённым и оплаченным. Новые приложения появляются во вкладке «Новые за последний поиск», общий уникальный список — во вкладке «Все находки». Оба списка можно выгружать в CSV.

Для публикаций, новостей, App Store и сайтов добавьте **BRAVE_SEARCH_API_KEY** через Render → Environment. Это отдельный ключ поискового сервиса, который не требуется для Google Play. Регистрация в Brave, лимиты, настройка ежедневного поиска и ограничения описаны в [SOCIAL.md](SOCIAL.md). В архиве настоящего ключа нет, доступ к нему ещё не проверен.

## Сохранение истории

При повторном развёртывании используйте **тот же сервис и тот же постоянный диск**. Не удаляйте диск и файл `/var/data/state.json`: в нём история, результаты и расписание. Без этого файла программа не знает о старых находках и сможет добавить их заново. Переименование приложения или его появление в другой стране не создаёт повтор: сравнение выполняется по package ID.

Если история уже накоплена на локальном компьютере, её файл `data/state.json` нужно отдельно перенести на постоянный диск перед первым облачным поиском. Архив с кодом не содержит личной истории. Пока файл не перенесён, новый облачный экземпляр считает историю пустой. Для резервной копии остановите сервис и сохраните копию `state.json` с диска; CSV сохраняет список, но не заменяет файл истории для восстановления.

## Если уже есть VPS

Можно использовать Dockerfile из проекта. Пример запуска на сервере с установленным Docker (из папки приложения):

```sh
docker build -t play-scout .
```

Создайте закрытый файл `play-scout.env` вне Git и запишите в него строку `APP_PASSWORD=ваш-длинный-случайный-пароль` с собственным значением. Затем выполните:

```sh
docker volume create play-scout-data
docker run -d --name play-scout --restart unless-stopped --env-file ./play-scout.env -e DATA_DIR=/var/data -p 127.0.0.1:3000:3000 -v play-scout-data:/var/data play-scout
```

Доступ снаружи настраивается через HTTPS-прокси с вашим доменом, направленным на порт 3000. Конкретные шаги зависят от сервера и домена. Веб-сервис рассчитан на одну копию процесса, использующую один файл истории. Порт Docker в примере открыт только самому серверу.

## Статус

Код и Docker-конфигурация подготовлены для Render, но платный сервис в вашем аккаунте ещё не создан. Проверка поисков с IP-адреса вашего будущего хостинга не выполнена. Фактические проверки версии 2.3, независимые живые результаты и ограничения источников перечислены в [VALIDATION.md](VALIDATION.md).

## Расширенный ежедневный поиск

После обновления до 2.3 откройте «Изменения и компании» → «Включить весь ежедневный мониторинг». У публикаций 8 Brave-запросов за запуск с дневной ротацией; 24 активные пары анонсов проходят за 3 дня непрерывной работы (все сигналы: 36 пар за 5 дней). Наблюдение за страницами и приложениями — отдельное расписание, без Brave-расхода. Все исходные состояния и события находятся на том же постоянном диске в `state.json.watch`. Для прямых страниц нужны публичная DNS-резолюция и HTTPS-доступ к их доменам; при ошибке последнее успешное состояние сохраняется.

## Веб-версии и исключения (2.3)

Новый веб-поиск использует тот же `BRAVE_SEARCH_API_KEY`, отдельное расписание 09:20 и отдельный бюджет 8 запросов за запуск по умолчанию. Настройте его во вкладке «Веб-версии» или включите весь ежедневный мониторинг. Данные находятся в `state.json.web`; общие исключения с возможностью восстановления — в `state.json.manualExclusions`. Переносите целиком файл истории и сохраняйте постоянный диск. Не запускайте второй процесс с тем же файлом. Бюджеты всех поисков суммируются; подробности в [WEB.md](WEB.md).

## Необязательная проверка через OpenAI

Добавьте `OPENAI_API_KEY` в секреты / Environment хостинга, при необходимости `OPENAI_MODEL=gpt-5-mini`, затем перезапустите сервис. Ключ Brave не заменяется. На вкладке «Нейронный поиск» отдельно включите дневной анализ и задайте лимит попыток; прежняя кнопка включения четырёх поисковых расписаний не включает платный OpenAI автоматически. По умолчанию ИИ выключен, месячный лимит 300 попыток, до 10 за запуск. Подробнее: [AI.md](AI.md). Постоянный диск сохраняет кэш, результаты и счётчик обращений после перезапуска. Лимиты считаются по календарю Калининграда и не являются денежным бюджетом.

В 2.4 общий сбор четырёх каналов включается во вкладке «Нейронный поиск»: отметьте автозапуск и сбор источников перед анализом. Месячный предел Brave по умолчанию 1000 запросов для всех каналов; для расширенного поиска добавьте `BRAVE_MONTHLY_REQUEST_LIMIT=2000` в Environment. Это не пополнение API-баланса. Категории «Новые» и «Ранние сигналы» и вся очередь сохраняются на постоянном диске.
