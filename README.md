## Запуск на Mac

Уже установленную версию обновляйте по **[готовому блоку команд](MAC.md#1-обновить-уже-установленный-play-scout-одной-командой)**. Переносить историю и ключи не требуется. После первого обновления доступны `4-Обновить.command` и `npm run update:mac -- "$PWD" --start`. Создаётся резервная копия, при ошибке установки прежний код восстанавливается.

Запуск — `bash ./2-Запустить.command`, остановка — `npm run stop`. Для вашего M5 / 16 ГБ есть отдельный [профиль llama.cpp / Metal](GPU_AGENT.md); Ollama остаётся доступной.

## Запуск на Windows

1. Установите Node.js LTS 22+ и распакуйте программу в `%USERPROFILE%\PlayScout`.
2. Для чистого запуска перенесите только `.env` с Mac через `9-Import-keys-only.cmd`. Папку `data` переносить не нужно. Либо задайте ключи заново через `4-Keys.cmd`.
3. Запустите `1-Install.cmd`, затем `2-Start.cmd`.
4. Для NVIDIA 8 ГБ / RAM 32 ГБ: [llama.cpp / CUDA и аппаратный профиль](GPU_AGENT.md); Ollama через `5-Local-AI.cmd` остаётся альтернативой.
5. Ключи и пароли настраиваются через `4-Keys.cmd`. Остановка — `3-Stop.cmd`, диагностика — `6-Diagnostics.cmd`.

Открыть **http://127.0.0.1:3000/crm**. Для доступа другим людям: отдельные пароли `admin` / `viewer`, локальная сеть или HTTPS через Tailscale Funnel. Пошагово — [в инструкции Windows](WINDOWS.md#10-дать-ссылку-людям-в-вашей-сети). Компьютер должен работать и не спать.

В терминале:

```sh
npm ci
npm run start:desktop
```

Для Linux остаётся `npm start`. [Полная инструкция Mac](MAC.md).

В 4.1.4 есть чистый Windows-старт с импортом **только ключей** и необязательный полный перенос профиля **Mac ↔ Windows** с шифрованием, резервной копией и откатом неудачного импорта. Поиск и правила отбора совпадают на обеих ОС. Подробно, от папок до команд: [WINDOWS.md](WINDOWS.md). Ключи берутся только из вашего локального `.env`; открытый ZIP их не содержит. Модель Ollama устанавливается на другом компьютере отдельно.

## Исправления качества в 4.1

В **[4.1.4](RELEASE_4_1_4.md)** исправлена обработка аргументов Mac-updater: `--start` больше не принимается за имя папки. Для перехода со старого скрипта укажите `"$PWD"` перед `--start`.

В **[4.1.3](RELEASE_4_1_3.md)** сокращены повторные пересчёты больших списков. После потери ответа браузер проверяет активное задание, не отправляя запуск повторно. Ключи, очередь и история сохраняются.

Проверка по реальной выгрузке выявила подмену проекта внешними ссылками, ошибки лицензий и слишком слабый отсев. В 4.1 добавлены:

- проверка названия и домена продукта, исключение виджетов Calendly и подобных сервисов;
- разделение регулятора и получателя разрешения, заявки и выдачи; распознавание двух разрешений PI + CASP;
- отдельная вкладка «Материалы источников»: общие инструкции регуляторов сохраняются без отправки в ИИ;
- отсев игр, локальных хранилищ карт / IBAN и налоговых инструментов, проверка нигерийской юрисдикции по смыслу полных текстов;
- выбор релевантных бизнес-страниц и проверка связей между цитатами о бизнес-счёте и EU IBAN;
- автоматическая локальная перепроверка старых результатов без API; отдельный адресный повторный ИИ-разбор по сохранённым текстам;
- диагностический JSON с моделью, версией правил, причинами unknown и оригинальным комментарием модели.

[Историческая инструкция к 4.1](RELEASE_4_1.md). При переходе на 4.4 комментарии и выбранный ИИ сохраняются, а прежние ручные исключения, кроме «Уже в работе / был в работе», возвращаются на проверку. Прежнее ежедневное расписание остаётся вашим; локальная перепроверка не является вызовом ИИ.

## Остальные функции

- Быстрые исключения в строках, выбор показанных / всей выборки и массовое исключение одним сохранением. Три причины с отдельной воронкой. В 4.4 прежние решения архивируются для нового прохода; действующими остаются исключения «Уже в работе / был в работе».
- Сопоставление известных названий бренда, регистров, диакритики, юридических / маркетинговых суффиксов, сайтов и ID. Упоминание исключённого банка как партнёра другого бренда не скрывает другой бренд само по себе. Результаты и исключения можно восстановить.
- Сортировка всех вкладок и отдельных списков по реальному релизу, публикации, дате решения о лицензии, обнаружению или названию. Неизвестные даты — в конце. Сортировка и причины учитываются в экспорте CRM.
- Ночной режим с запоминанием в браузере.
- App Store отключён в новых заданиях и расписаниях. Старая история доступна в архиве.
- Лицензии: регуляторный материал → извлечение названий и разрешений → поиск сайта → чтение продукта → отдельный разбор сайта в той же очереди. Неподтверждённый сайт не выдаётся за официальный; лицензия не подтверждает доступность бизнес-счёта / EU IBAN.
- Подтверждённые совпадения требуют прямых источников продукта. Общие статьи, лицензия сама по себе, EUR / SEPA и shared/deposit-only IBAN остаются на проверку. Работа через лицензированного партнёра допустима.
- Ollama с коротким протоколом и прогрессом, OpenAI API и дополнительный Gemini API. Параллельность облака регулируется, локальный разбор выполняется последовательно. Платного резервного переключения нет.
- YouTube, публичные индексы Meta / LinkedIn / Google / TikTok рекламы, RSS, партнёры, Trustpilot, новости и реестры. Полная рекламная лента и закрытые соцсети не подключены: [точное покрытие](SOCIAL_CONNECTIONS.md).
- Общая база с отдельным серверным режимом просмотра: `viewer` не может менять данные, запускать поиск и расходовать API.

«Новый» означает первое обнаружение, а не дату создания компании. Кабинет отмечается по публичным сведениям / ссылкам: вход и открытие счёта не выполняются. Сведения о продукте и разрешении — цитаты источников, а не гарантии открытия вашей компании.

## Данные и проверка

Полная история — `data/state.json`. Ключи и пароли — `.env`. Архив кода их не содержит. Перед обновлением остановите приложение и сохраните оба файла / папку. Word, CSV и JSON выгружаются с учётом вкладки, причин, поиска и сортировки.

```sh
npm run check
npm test
```
