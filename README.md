Отдельный проект для Windows / macOS и Chromium-профилей Dolphin. Целевая версия Dolphin, указанная пользователем, — **307.36437**. Сервер работает на Node.js 24 / Linux, пользователю нужен браузер и расширение. Общедоступный сервер автоматически не создавался.

## Автоматическое обновление

[Первое обновление одной командой PowerShell](docs/AUTO-UPDATE.md). После перехода на 0.2.1 — двойной щелчок по `Update-Windows.cmd` или `npm run update -- --start`. Код скачивается из GitHub, проверяется и обновляется с копией и откатом; `data` и `.env` сохраняются. Переход со старой версии требует один раз остановить её окно.

## Основной сценарий

1. Создайте карточку компании.
2. Заполните простую форму **«Заполнить форму и создать блокнот»** или загрузите существующий TXT. Форма может скачать заполненный блокнот и пустой шаблон; готовый шаблон лежит в [templates/company-info-template.txt](templates/company-info-template.txt).
3. Загрузите документы: PDF, DOCX, TXT, PNG, JPG. До 8 файлов, до 15 МБ каждый. PDF: до 60 текстовых / до 8 сканированных страниц; фото до 16 мегапикселей. OCR английского / русского выполняется локально на сервере.
4. Приложение само разбирает понятные сведения, приводит их к единым полям карточки и сопоставляет источники. Совпадения можно раскрыть; расхождения требуют выбора итогового значения. Имена, даты, реквизиты и цитаты не нужно копировать по одному вручную.
5. Проверьте итоговую карточку. Отметьте **«Я проверил(а) все итоговые данные…»** и нажмите **«Подтвердить итоговые данные»**. Пока есть неразрешённые расхождения, заполнение заблокировано.
6. В Dolphin откройте панель расширения, выберите компанию и контактное лицо. Нажмите **«Заполнить найденные пустые поля»** или включите автоматическое заполнение новых пустых полей.
7. Проверьте анкету на сайте и отправьте её самостоятельно.

После новых документов или изменения итоговых сведений общее подтверждение перестаёт действовать. Перед каждой вставкой расширение повторно проверяет версию данных. Уже введённые значения, пароли, коды, подписи и согласия не меняются автоматическим режимом.

## Сопоставление полей

У веб-интерфейса, формы блокнота и расширения единый справочник. Например:

| Поле на сайте | Поле карточки |
|---|---|
| Website / Web site / Company URL / Site | Сайт компании |
| First name / Given name / Forename | Имя выбранного контактного лица |
| Last name / Surname / Family name | Фамилия выбранного контактного лица |
| Work email / Business email | Email компании |
| Country of incorporation / Registration country | Страна регистрации |
| Message / Anything else we should know | Краткое описание бизнеса |

Дополнительно учитываются внутренние имена (`first_name`, `firstName`), autocomplete браузера, регистр, стандартные необязательные пометки, допустимые варианты страны и явный формат даты. Телефон с международным кодом может разделяться на Dial code и Phone number. Оборот не заменяет объём операций, налоговое резидентство не заменяется страной регистрации.

Двухчастное латинское имя из обычного личного блока разделяется как «имя → фамилия» с видимым пояснением; оператор проверяет порядок перед общим подтверждением. Составные имена без явных подписей не разбиваются наугад. Директор, бенефициар и контактное лицо не объявляются одним человеком без сведений о роли.

## Локальный запуск Windows

Для предварительной проверки установите Node.js 24 LTS с https://nodejs.org, распакуйте проект и запустите `Install-Windows.cmd`: установка зависимостей и создание пользователя. Затем `Start-Windows.cmd` и `http://127.0.0.1:3100`. Окно запуска должно оставаться открытым. Дополнительные пользователи: `node scripts/create-user.js` в папке проекта. Всего до трёх пользователей; карточки разных пользователей изолированы.

Если уже пользовались версией 0.1 / 0.2, используйте [автоматический переход одной командой](docs/AUTO-UPDATE.md). Он сохранит прежние данные и пользователей без ручного переноса папок.

## Необязательный ИИ

Без API работают форма, разбор структурированного блокнота, локальное OCR, сопоставление типовых полей, сравнение источников и вставка.

При настроенных `AI_API_KEY` / `AI_MODEL` доступны русские пояснения вопросов и кнопка смыслового разбора сложных текстов. Пояснение отправляет только текст вопроса. Смысловой разбор документов **отправляет их текст, включая персональные сведения, OpenAI API только после отдельного подтверждения в интерфейсе**. Цитаты и значения проверяются сервером; факты без источника отклоняются. Внешний API с настоящими документами в разработке не вызывался.

Исправления в панели сохраняются для компании, домена и вопроса и останавливают обычную подсказку на этом поле. Это память правил, а не дообучение весов модели. Неоднозначное поле не заполняется по догадке.

## Проверки разработчика

```sh
npm ci --ignore-scripts
npm run check
npm test
node scripts/verify-browser.js
```

Для последней команды нужен установленный Chromium (`CHROMIUM_PATH` при нестандартном расположении). Проверяется настоящий веб-интерфейс и DOM панели с **имитацией runtime расширения** на вымышленных данных. `scripts/verify-container.js` проверяет production-образ. Настоящая загрузка расширения — отдельный `scripts/verify-extension.js`; в облаке она запрещена администраторской политикой и не считается пройденной.

## Ограничения

Сопоставление не гарантирует поддержку всех сайтов и формулировок. Не поддержаны iframe, закрытый Shadow DOM, canvas, нативные банковские приложения и произвольные нестандартные виджеты. Непонятные поля остаются без автоподстановки. Проверки не доказывают подлинность документов или юридическую правильность ответов; итоговую версию подтверждает оператор.

Оригиналы, извлечённый текст, карточки и исправления хранятся на сервере с авторизацией и файловыми правами. Отдельное прикладное шифрование файлов, 2FA и восстановление пароля через интерфейс пока не реализованы. Для рабочего сервера нужны HTTPS, защищённое хранение и резервные копии. Нативные Windows / macOS, настоящий Dolphin и выбранный API требуют проверки в месте использования.
