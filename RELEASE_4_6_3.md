# Play Scout 4.6.3 — новый поиск без старой очереди

Добавлена отдельная очистка накопленных результатов с сохранением проектов
«В работе / был в работе». Она выполняется **только по явной команде**, после
остановки приложения. Установка обновления сама базу не очищает.

Перед изменениями создаётся приватная самостоятельная резервная копия полной
истории, включая ещё не собранный журнал. Если копию создать нельзя, очистка
не выполняется. Команда сначала проверяет, что локальный порт приложения свободен.
Предварительный просмотр не меняет файлы.

Остаются карточки, комментарии и сохранённые разборы проектов в работе.
Их известные домены, приложения и названия сохраняются в правилах исключения;
потеря старых связующих результатов больше не лишает их защиты. Статьи, в которых
такой проект является главным предметом, также исключаются. Упоминание партнёра
в статье о новой компании само по себе её не исключает. Исключение одной статьи
не превращается в запрет всего издательства. Для записей только с названием
поддерживается отдельное правило имени, без выдуманного домена.

Остальные находки Google Play / сайтов / публикаций / наблюдения / App Store,
прежние ручные решения и исключения не из категории «В работе», старые разборы,
кеш разборов, архивы, копии прежнего цикла проверки, история запусков, очереди
Google Play и ИИ удаляются из активной базы. Проекты в работе собираются в
сохранённые карточки CRM; старая очередь не продолжается. Удалённые карточки
не переносятся в новый чёрный список — при новом обнаружении действуют текущие
критерии поиска.

**Сохраняются** `.env`, ключи, действующие фильтры / страны / исключаемые
юрисдикции / правило чистых криптокошельков, модель ИИ, аппаратный профиль,
расписания, реестр ориентиров с его текущими флагами и учёт расхода API.
Реестр ориентиров — отдельная настройка, не очередь старых находок.
Если чистый криптокошелёк уже был вручную отмечен как «В работе», его карточка
и комментарий сохраняются только в этой защищённой категории; новые кошельки
по-прежнему не допускаются в поиск и очередь ИИ.
Очистка не вызывает поиск / сайты / облачный ИИ и не расходует их баланс.

В CRM появится строка «База очищена» с датой и числом сохранённых проектов
в работе. После очистки старые карточки не восстанавливаются из jobs, inbox,
manualBatch, reviewCache или прежних копий цикла. Будущие находки проходят
обычные текущие фильтры; очистка сама не подтверждает пригодность новых сервисов.

## Команды

Предварительный просмотр после остановки программы:

```bash
npm run history:clean
```

Очистка с обязательной резервной копией:

```bash
npm run history:clean -- --apply
```

На Windows используйте `npm.cmd`. Команда напечатает точный путь к копии
`state.json.before-history-clean-….json`. Это отдельный полный снимок: он хранится
для восстановления, но не читается приложением как рабочая база. Не удаляйте его
до проверки результата. Для отката используйте согласованную копию кода и
истории: старый код не поддерживает новые правила исключения по имени.
Для обычных резервных копий по-прежнему сохраняйте всю
папку `data` и `.env`.

Причина предупреждения XProtect на Mac остаётся неустановленной. Очистка не
считается исправлением блокировки. После неё используйте
`npm run start:diagnostic`, чтобы посмотреть сохранённую CRM без внешних заданий.
Полную проверку с повторным срабатыванием пока не возобновляйте.
