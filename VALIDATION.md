# Исправление Windows EPERM · версия 0.2.2 · 4 ноября 2026

- Удалено переименование каталогов `node_modules` при установке и откате. Вместо него выполняется синхронизация файлов в существующем каталоге, пропуск неизменившихся файлов и проверка SHA-256 содержимого. Устаревшие файлы удаляются; относительные ссылки `.bin` сохраняются.
- **34/34 теста**: дополнительно проверены сценарий запрета переименования каталогов, неизменность каталога назначения, сохранность старых зависимостей, удаление устаревших файлов / ссылки и невозможность превратить успешное обновление в ошибку из-за заблокированной временной staging-папки. Откат и контрольные суммы по-прежнему проверяются.
- Полный переход **0.2.0 → 0.2.2** и последующее обновление работающей версии до тестовой **0.2.3** выполнены с настоящими npm-зависимостями и серверными процессами на Linux. Сохранены учётная запись, сессия, документы, `.env` и запись, добавленная во время подготовки. 0.2.3 используется только в тесте и не публикуется.
- Пользовательский скриншот подтверждает, что в Windows 0.2.1 прошли загрузка, подготовка и проверка зависимостей, а ошибка возникла при `rename` каталога из staging в `node_modules` внутри OneDrive Desktop. Исправление убирает именно эту операцию. Причина конкретной блокировки Windows не устанавливалась по системным журналам; фактический повторный запуск 0.2.2 на устройстве пользователя ещё необходим.

# Проверки версии 0.2.1 · автоматическое обновление · 4 ноября 2026

- Node.js 24.22.1 / Linux: **31/31 тест**, без пропусков и отмен. Существующие сценарии документов и заполнения сохраняются; добавлены проверки SHA-256, ZIP / CRC, путей и ссылок, сохранности пользовательских данных и настроек, отката к прежним коду / зависимостям / базе и отказа от остановки чужого сервиса.
- Приватное локальное управление проверено на настоящем процессе сервера: health не раскрывает ключ остановки; неверный ключ отклоняется, правильный штатно завершает процесс. Ключ хранится только в локальном служебном файле с ограниченными правами.
- Полный переход **0.2.0 → 0.2.1** выполнен в отдельной временной установке: настоящий ZIP старой версии, настоящее `npm ci` с frozen lockfile и проверкой integrity, OCR / функциональная проверка временной версии, копия базы и файлов, запуск, вход прежним пользователем и чтение прежней компании. `.env`, пользовательский файл и оригинал документа сохранены.
- Затем выполнен полный цикл **работающая 0.2.1 → тестовая 0.2.2** с имитацией только источника релиза. Старое приложение продолжало принимать данные во время подготовки; после подготовки было штатно остановлено и запущено новое. Добавленная во время подготовки запись и прежняя сессия сохранились. Тестовая 0.2.2 не публикуется как релиз.
- Повторная проверка актуальной версии не меняет файлы и не перезапускает работающий экземпляр.

ZIP и метаданные публикации проверяются после загрузки с GitHub. Сценарий Windows FolderBrowserDialog, Windows-блокировки файлов и перезагрузка расширения в Dolphin в облаке не исполнялись. Проверки выполнены на Linux с настоящими Node.js-процессами; нативный Windows-запуск нужно проверить на устройстве пользователя. Обновлятор предназначен для установки с прямым запуском Node.js; Docker обновляется на хосте отдельно. Временное выключение питания посреди замены не равно проверенному откату при обычной ошибке; в таком случае остаётся журнал и копия для восстановления.

# Проверки версии 0.2.0 · 4 ноября 2026

- Node.js 24.22.1 / Linux: `npm run check`, **24/24 теста**, без пропусков и отмен. Проверены чтение PDF / DOCX / изображений и сканированного PDF, автоматический разбор структурированного и обычного блокнота, раздельные имя / фамилия, единый справочник названий, форматы страны и даты, отсутствие смешивания ролей, повторяемость разбора, конфликты источников и их разрешение.
- Проверены общее подтверждение оператором и его снятие после нового документа / изменения данных. Без актуального подтверждения `/api/propose` не разрешает вставку. Токен расширения не может подтвердить карточку за оператора.
- Семантический разбор проверен **с имитацией API**: цитата, страница и значение должны существовать в источнике, выдуманные реквизиты и команды отклоняются. Настоящий API и настоящие документы пользователя во внешний ИИ не отправлялись.
- Chromium 155: реальный веб-интерфейс, сохранение блокнота и формы оператора, совпадения в источниках, общая галочка, английская форма с полями как на скриншоте пользователя. Проверены First name / Last name, Website, Company name, страна в select и Message, пакетное заполнение, отсутствие замены существующего значения, память исправлений и заполнение динамически появившегося поля. **Runtime расширения имитируется**; это не проверка установки новой версии в Dolphin.
- Production Docker-образ 0.2.0 собран. В контейнере Node.js 24.22.2 проверены вход, загрузка PNG, локальное OCR, подтверждение источника и итоговой версии, предложение значения.
- Предоставленный пользователем TXT локально разобран в 19 типов сведений. Персональные значения не включены в код, тесты, ZIP или GitHub. Телефон и email, отсутствующие в источнике, не выдумываются.

Остаются непроверенными: новая версия расширения в реальном Dolphin / Windows / macOS, конкретная API-модель, реальные сайты и сложные виджеты, публичное развёртывание, нагрузка трёх пользователей и подлинность официальных документов. Программа сопоставляет сведения и цитаты, а не удостоверяет документы. Проверенные источники и итоговую версию подтверждает оператор.

# Проверки версии 0.1.0 · 4 ноября 2026

## Пройдено

- Linux, Node.js **24.22.1**: установка зависимостей с сохранённым lockfile, `npm run check`.
- `npm test`: **12 тестов, 12 пройдено**, без ошибок, пропусков и отмен. Проверены реальные текстовый PDF, DOCX, растровый скан и PDF без текстового слоя; отказ для повреждённых файлов; авторизация; разделение пользователей; подтверждение значения по существующей цитате; область действия исправлений; отзыв токена; ограничения service worker; резервная копия базы и оригиналов.
- Интерактивное создание пользователя через `scripts/create-user.js` проверено на Linux: ввод и повтор пароля скрыты, учётная запись сохраняется. Windows-лаунчеры записаны в ASCII / CRLF; это не подтверждает их нативное выполнение на Windows.
- Chromium **155.0.8059.79**: реальный веб-интерфейс, создание компании и заметки, сохранение подтверждённого значения, отображение недоверенного текста без исполнения HTML, вставка в тестовую анкету по нажатию, исключение секретных полей, память исправлений и обнаружение динамически добавленного поля. Проверены ручное сопоставление незнакомого вопроса и отказ от значения, не подходящего по длине. **Runtime расширения имитируется**, само расширение в этой проверке не устанавливается.
- Docker-образ `registration-assistant:onboarding` собран. Проверка внутри минимального production-образа на Node.js **24.22.2**: вход, создание компании, загрузка известного PNG-скана, локальное OCR, подтверждение источника и предложение значения. Приложение запускается от пользователя `node`, не root.
- `docker compose --env-file .env.example config --quiet`: конфигурация развёртывания валидна на тестовом домене.
- Установка production-зависимостей при сборке Docker: npm сообщил **0 известных уязвимостей**. Это результат проверки базы npm на момент сборки, не аудит приложения.

В проверках использованы вымышленные сведения `Example Limited`. Живые банковские регистрации не выполнялись, платные API не вызывались.

## Заблокировано в облачном стенде

Настоящая загрузка распакованного расширения в Chromium запрещена администраторской политикой. Браузер вернул: `Loading of unpacked extensions is disabled by the administrator.` Ограничение не обходилось. Проверка `scripts/verify-extension.js` **не пройдена**; тесты service worker и панели с имитацией runtime не доказывают успешную установку расширения.

## Ещё не проверено / не выполнено

- Установка расширения в **Dolphin 307.36437 на Windows** — следующий обязательный шаг перед рабочим использованием.
- Нативная установка на Windows и macOS; macOS-профиль Dolphin.
- Подключение конкретной платной API-модели и качество её русских пояснений.
- Настоящие банковские сайты, нестандартные формы и вложенные iframe.
- Публичный сервер, DNS и выпуск HTTPS-сертификата: сервер / домен пользователя не предоставлены. Compose и инструкция подготовлены, публикация не выполнялась.
- Производительность при трёх одновременных пользователях на выбранном хостинге; проверка OCR в контейнере не является нагрузочным тестом.
- Восстановление Docker-тома из копии: создание копии и её чтение проверены тестом, полная аварийная процедура на отдельном сервере не выполнялась.

Первая версия предназначена для пилота на тестовых данных. Для реальных банковских документов нужны проверка Dolphin, настройка серверного доступа / хранения и подтверждение каждого значения человеком.
